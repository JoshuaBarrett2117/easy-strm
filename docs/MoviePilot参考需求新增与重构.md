# 媒体库管理需求新增与重构

- 日期：2026-05-06
- 执行者：Codex
- 状态：需求草案
- 适用范围：easy-strm 后端、easy-strm-front 前端、docs 文档

## 1. 背景

easy-strm 当前主链路已经覆盖“媒体源接入 -> 文件浏览 -> TMDB 识别 -> 重命名/整理 -> STRM 生成 -> 任务追踪”，具备本地媒体源、115 媒体源、TMDB、Emby、自动整理、任务中心等基础能力。

MoviePilot 的公开定位是 NAS 媒体库自动化管理工具，强调聚焦自动化核心需求、减少设置复杂度、前后端分离和插件扩展；其典型能力包括搜索订阅、下载后自动整理、媒体库刷新、通知、插件市场与多媒体服务器协同。

结合新的产品边界，本轮还参考 Symedia、cloud-media-sync、q115-strm 这类 STRM/云端媒体库同步工具，但只吸收“媒体库管理”相关能力：115 与本地媒体库同步、STRM 生成、增量检测、自动整理、元数据处理、Emby 联动、任务可观测。easy-strm 不接入 PT、不接入下载器、不做资源站聚合，产品主线收敛为“115 + 本地媒体库管理”。

## 2. 产品定位调整

### 2.1 调整前

easy-strm 更偏向“媒体文件整理与 STRM 生成工具”，用户需要在多个页面里完成媒体源、识别、整理、STRM、Emby 刷新和任务查看。

### 2.2 调整后

easy-strm 调整为“面向 115 与本地目录的媒体库管理工作台”，核心目标是让用户把 115 网盘目录和本地媒体目录纳入统一管理后，系统自动完成目录索引、增量检测、识别命名、归档整理、STRM 映射、元数据同步、媒体服务器刷新与结果反馈。

### 2.3 本轮原则

1. 优先增强已有链路，不新增资源站、PT 站点、下载器体系。
2. 以媒体源为入口组织自动化规则，而不是新增分散配置页。
3. 以任务中心作为统一事实来源，所有自动化动作必须可追踪、可重试、可解释。
4. 复用现有 Go + Gin + PostgreSQL + Redis + Vue 3 + Element Plus 技术栈。
5. 功能新增与重构同步推进，避免继续扩大旧接口与新接口并存的维护面。
6. 115 与本地目录为本轮一等媒体源，其它网盘只保留抽象，不进入实现范围。

## 3. 目标用户与场景

### 3.1 目标用户

- 使用 115 或本地目录存放影视资源的个人用户。
- 使用 Emby 管理媒体库，并希望减少手工整理操作的用户。
- 已经依赖 `.strm` 方式播放云盘资源，希望提升入库稳定性的用户。

### 3.2 核心场景

1. 用户配置 115 或本地媒体源，指定源目录、媒体库目录、同步模式、整理规则、命名规则、STRM 输出和 Emby 媒体库。
2. 系统完成一次全量索引，建立“源文件 -> 本地媒体库文件/STRM 文件 -> 媒体服务器路径”的映射关系。
3. 新文件或变更出现后，系统通过本地事件、115 增量事件、Webhook 或智能轮询触发同步。
4. 系统自动识别媒体信息，按规则整理到目标媒体库目录，并生成或更新 STRM、元数据和媒体服务器刷新任务。
5. 如果识别、重命名、整理、STRM、元数据或 Emby 刷新失败，用户可以在任务中心查看失败原因并一键重试失败步骤。

## 4. 功能需求

### FR-001 自动化规则中心

将媒体源配置扩展为“自动化规则”的承载实体，每个媒体源可以配置一套默认自动化策略。

需求：

- 支持启用或停用自动化规则。
- 支持配置监控路径、整理目标路径、媒体类型、冲突策略、操作模式。
- 支持配置命名模板，区分电影、电视剧、季集格式。
- 支持配置后续动作：生成 STRM、刮削元数据、刷新 Emby。
- 支持配置执行顺序，默认顺序为：识别 -> 整理 -> STRM -> 刮削 -> Emby 刷新。
- 支持规则预检，保存前提示缺失的 TMDB、Emby、115 账号或路径配置。

验收标准：

- 媒体源列表可以直接看出自动化是否启用、下一次检查时间、最近一次执行结果。
- 自动化规则保存后，本地监控与 115 轮询均使用同一套规则字段。
- 规则缺失关键字段时不能静默失败，必须返回可读原因。

### FR-002 媒体库同步引擎

新增面向 115 与本地目录的统一同步引擎，参考 cloud-media-sync、q115-strm 的“全量同步 + 增量同步 + 变更对账”模式。

需求：

- 支持全量同步：扫描源目录和目标媒体库目录，生成完整文件索引。
- 支持增量同步：对新增、修改、删除、移动、重命名进行差异处理。
- 115 媒体源优先使用 115 生活事件作为低请求量增量依据；生活事件不可用或检测到事件缺口时，回退到定时差异对账。
- 115 定时差异对账默认间隔为 30 分钟，允许按媒体源配置；低于 30 分钟时需要在前端明确提示接口请求与风控风险。
- 本地媒体源使用文件系统事件监听，异常退出后可通过索引对账恢复。
- 支持同步模式：仅生成 STRM、复制本地文件、移动本地文件、软链接、硬链接。
- 支持源文件删除后的目标处理策略：保留、标记失效、删除 STRM、删除空目录。
- 支持手动触发单目录同步，正在同步时跳过重复任务并提示原因。

验收标准：

- 完成一次全量同步后，增量同步只处理变更文件。
- 源端删除、目标端缺失、pick_code 变化或本地路径变化都能产生明确差异记录。
- 同步任务必须记录扫描数量、变更数量、跳过数量、失败数量和耗时。

### FR-003 入库流水线任务

新增“入库流水线”概念，将一次自动化处理抽象为父任务，内部包含识别、整理、STRM、刮削、Emby 刷新等步骤。

需求：

- 新增任务类型 `library_pipeline`。
- 父任务记录媒体源、来源路径、目标路径、文件列表、触发方式、当前阶段。
- 子步骤记录状态、耗时、输入摘要、输出摘要和失败原因。
- 支持失败后从失败步骤继续重试。
- 支持手动触发：用户在文件浏览器选择文件后，可以发起“按自动化规则入库”。

验收标准：

- 任务中心能按父任务展示完整链路，而不是分散的多个孤立任务。
- 任一步骤失败后，已完成步骤不重复执行，除非用户选择“完整重跑”。
- 自动整理任务和手动整理任务在任务中心展示语义一致。

### FR-004 识别与待处理清单

借鉴 MoviePilot 的“待处理/订阅状态”思想，但本轮不接入资源站、PT、RSS 和下载器；新增“待处理清单”，用于承接识别失败、手动加入、媒体库补全和未来扩展。

需求：

- 支持将文件、目录或 TMDB 条目加入待处理清单。
- 待处理项包含标题、年份、媒体类型、季、集、来源路径、目标媒体源、处理状态。
- 自动识别失败时，自动生成待处理项并关联原任务。
- 用户可以在清单中手动修正 TMDB 条目后重新入库。
- 预留 `source_kind` 字段：manual、watch、sync、tmdb、future_extension。

验收标准：

- 识别失败不再只停留在任务错误消息中，必须进入可操作的清单。
- 手动修正后可以回到同一条入库流水线继续执行。
- 不引入 PT 站点、RSS、下载器和站点 Cookie 管理。

### FR-005 命名模板与媒体分类重构

统一当前重命名、整理、分类策略之间的字段与行为。

需求：

- 抽象命名模板实体，支持电影、电视剧、动画三类模板。
- 模板变量来自统一识别结果：标题、原名、年份、季、集、集标题、分辨率、视频编码、音频编码、来源、发布组。
- 分类策略可以基于媒体类型、类型标签、国家/地区、年份范围、关键词命中决定目标目录。
- 预览结果必须展示模板变量解析结果、目标路径、冲突判断。
- 当前更名预览与整理预览复用同一套命名计算逻辑。

验收标准：

- 相同文件在“重命名预览”和“整理预览”中生成一致的新文件名。
- 冲突策略 skip、overwrite、suffix 在预览与执行阶段结果一致。
- 模板字段缺失时展示明确占位原因，不能生成空目录或异常文件名。

### FR-006 STRM 映射与媒体库刷新联动

把 STRM 生成从独立配置页能力升级为媒体库同步与入库流水线中的核心步骤。

需求：

- 自动化规则可选择是否生成 STRM。
- STRM 输出目录默认跟随整理目标，也允许独立配置。
- 支持全量生成、增量生成和单条文件刷新。
- STRM 内容支持直链、代理链接、本地路径、OpenList/Alist 风格路径模板。
- 115 直链刷新策略独立配置，避免每次扫描都请求直链。
- 支持 STRM 失效检测：源文件不存在、pick_code 变化、路径映射变化。
- 整理成功后，仅对本次新增或变更文件执行增量 STRM。
- STRM 成功后可触发 Emby 指定媒体库刷新。
- Emby 刷新结果必须写回任务步骤。

验收标准：

- 115 文件自动整理成功后，可以自动完成 STRM 增量更新。
- 本地文件整理成功后，如果未启用 STRM，则跳过该步骤并记录为 skipped。
- Emby 未配置时，不阻断整理与 STRM 主流程。
- STRM 文件命名和目录结构必须符合 Emby 可识别的媒体命名规则。

### FR-007 元数据与海报墙管理

参考 Symedia、q115-strm、cloud-media-sync 的媒体库补全能力，新增元数据管理需求，但不强制替代 Emby 自身刮削。

需求：

- 支持 NFO、poster、fanart、subtitle 等同名伴随文件识别与同步。
- 支持从源目录同步已有元数据到本地媒体库目录。
- 支持按策略生成 NFO 与图片文件：关闭、仅缺失时生成、强制刷新。
- 支持仅上传或同步 Emby 已生成的标准媒体图片到 115 目标目录。
- 支持按媒体条目展示元数据完整度：NFO、海报、背景图、字幕。
- 支持批量修复缺失元数据，结果进入任务中心。

验收标准：

- 对于已有 Emby 刮削结果的本地媒体库，系统不会默认覆盖现有 NFO 和图片。
- 115 与本地媒体库在元数据文件处理上使用同一套同步记录。
- 元数据生成失败不影响 STRM 主文件生成，但必须在任务步骤中可见。

### FR-008 媒体库视图与资产台账

新增“媒体库视图”，从文件操作工具升级为可浏览、可筛选、可诊断的媒体库管理台账。

需求：

- 按电影、电视剧、动画、未识别、缺失元数据、STRM 失效、重复文件等维度查看媒体库。
- 支持查看单个媒体条目的源文件、目标文件、STRM 文件、元数据文件、Emby 库状态。
- 支持重复媒体检测：同 TMDB、多版本、同 SHA1、同 pick_code、同标题年份。
- 支持失效项诊断：源文件缺失、STRM 指向无效、Emby 未入库、元数据缺失。
- 支持批量操作：重新识别、重新生成 STRM、刷新元数据、刷新 Emby、移入待处理。

验收标准：

- 用户不需要进入原始文件浏览器，也能知道媒体库当前健康状态。
- 每个媒体条目都能追溯到来源媒体源和最近一次处理任务。

### FR-009 插件化能力边界

MoviePilot 的插件能力很强，但 easy-strm 本轮只做“内部扩展点梳理”，不做插件市场。

需求：

- 梳理可扩展动作：通知、媒体服务器刷新、元数据刮削、后处理命令。
- 后端以接口方式隔离动作执行，先内置实现，不提供第三方插件安装。
- 前端在自动化规则中以“后续动作”方式展示，不展示插件市场概念。
- 预留动作执行结果结构，统一接入任务中心。

验收标准：

- 新增一个后续动作时，不需要改动任务中心展示结构。
- 用户界面不出现“插件市场”“安装插件”等入口。

### FR-010 通知与可观测性

增强任务中心和通知配置，让自动化结果对用户可解释。

需求：

- 通知事件分级：入库成功、部分成功、失败、需要人工处理。
- 通知内容包含媒体标题、来源媒体源、成功/失败数量、失败阶段、可操作入口。
- Dashboard 首页展示今日入库数量、失败待处理数量、最近失败原因 Top 5。
- 日志中心支持按 task_id 过滤相关日志。

验收标准：

- 用户收到失败通知后，可以直接定位到任务中心中的对应任务。
- Dashboard 不再只是系统状态概览，而能反映媒体入库健康度。

## 5. 重构需求

### RR-001 任务模型重构

当前任务状态已具备 `metadata`、进度、失败数量等字段，但缺少父子步骤结构。本轮需要在不扩散临时字段的前提下，统一任务模型。

要求：

- 新增任务步骤表或等效结构，记录步骤状态。
- 统一任务状态枚举：pending、running、completed、failed、cancelled、skipped。
- 所有 service 写入任务时使用统一 TaskService 接口。
- 前端 TaskCard 支持步骤时间线。

### RR-002 同步索引模型重构

新增统一同步索引，用于支撑全量同步、增量同步、STRM 失效检测和媒体库资产台账。

要求：

- 记录源文件唯一标识：本地路径或 115 file_id/pick_code/sha1。
- 记录目标文件路径、STRM 路径、元数据路径、媒体服务器路径。
- 记录最近同步时间、最近变更类型、最近任务 ID。
- 支持按媒体源、路径、TMDB ID、pick_code、sha1 查询。

### RR-003 媒体源模型重构

当前媒体源已经包含监控、自动整理、Emby 字段，需要继续收敛为自动化规则。

要求：

- 保留媒体源基础字段，新增自动化规则字段组。
- 字段命名按业务含义统一：watch、identify、organize、strm、scrape、media_server。
- 数据迁移必须把现有 `auto_organize`、`watch_enabled`、`organize_target_path` 等字段映射到新结构。

### RR-004 识别结果模型重构

当前 TMDB 识别、重命名、整理预览之间存在字段重复。

要求：

- 新增统一 `MediaIdentity` 或等效结构。
- 所有命名、分类、刮削、STRM 决策均从统一识别结果读取。
- 手动识别覆盖项写回识别缓存，避免同一文件反复人工处理。

### RR-005 前端信息架构调整

当前页面已分为仪表盘、任务中心、文件管理、STRM、115、整理规则、设置。本轮建议调整为：

1. 仪表盘：媒体入库健康度、待处理、最近任务。
2. 媒体库：媒体条目、STRM 状态、元数据完整度、重复与失效诊断。
3. 待处理：识别失败、人工修正、重新入库、批量处理。
4. 同步任务：全量同步、增量同步、入库流水线、失败重试。
5. 自动化规则：媒体源规则、命名模板、分类策略、后续动作。
6. STRM 与媒体服务器：STRM 配置、路径映射、Emby/Jellyfin/Plex 预留配置、刷新记录。
7. 运维：任务中心、日志、网络、缓存、系统设置。

## 6. 非目标

本轮明确不做：

- PT 站点管理、站点 Cookie 同步、CookieCloud。
- qBittorrent、Transmission、下载器接入。
- Overseerr、Jellyseerr、Radarr、Sonarr 兼容服务。
- 插件市场、第三方插件安装、在线插件仓库。
- 多网盘接入扩张；本轮只做 115 与本地目录。
- 多用户权限体系。
- 公网部署与远程协作能力。

## 7. 数据与接口草案

### 7.1 新增或调整的数据对象

| 对象 | 说明 |
| --- | --- |
| AutomationRule | 媒体源自动化规则，承载识别、整理、STRM、刮削、媒体服务器刷新配置 |

## 9. 验收总标准

1. 115 和本地媒体源都可以完成全量同步、增量同步和差异对账。
2. 新文件进入启用自动化的媒体源后，可以自动完成入库流水线。
3. 所有步骤状态在任务中心可见，失败原因可读，失败项可重试。
4. 手动整理和自动整理复用同一套识别、命名、分类和任务模型。
5. STRM 与 Emby 不再只是独立页面操作，而能作为媒体库同步和入库流水线步骤被编排。
6. 媒体库视图可以展示条目健康度、STRM 状态、元数据完整度和最近处理任务。
7. 未配置外部能力时，主流程以 skipped 或可读失败呈现，不出现静默中断。
8. 文档、接口、测试用例随实现同步更新。

## 11. 已确认产品决策

以下问题已按本轮反馈收敛为实现决策：

1. 待处理清单作为独立页面，不并入媒体库页面；它承担识别失败、人工修正、重新入库和批量处理入口。
2. STRM 输出目录采用“规则默认 + 配置覆盖”策略：默认跟随整理目标生成媒体库同构目录，已有 STRM 配置继续作为高级覆盖项；媒体源自动化规则可单独指定 STRM 输出根目录、路径模板和链接模板。
3. 115 增量同步采用“生活事件优先 + 定时差异对账兜底”：参考 cloud-media-sync 的 115 生活事件低请求量增量思路；参考 q115-strm 的定时文件树对比思路，默认差异对账间隔为 30 分钟，并支持按媒体源配置。
4. 媒体服务器字段需要预留 Emby、Jellyfin、Plex，但本轮优先实现 Emby；接口和数据模型使用通用 `media_server` 命名，避免后续只能绑定 Emby。
5. 动画本轮不作为独立媒体类型，先作为电视剧模板的扩展分类处理；后续如果动画规则明显分化，再升级为独立类型。
