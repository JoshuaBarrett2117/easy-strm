- 原实现不是空队列必然无限循环：`DirtyBatch` 为空即退出；真实 RED 证明五个作品会调用五次 `prepareSelectionWork(work)`，重复 schema/sync/resolve。DAO 的非空 work 参数有作品范围谓词，不能将其描述成五次 `SyncSelections("")`；它仍重复扫描/物化基础关系。全量完成会原子播种 dirty，155,023 个文件写完不等于作品检查点已确认。
- 消费先探测队列，空队列不执行 selection 准备；可信增量或 building 恢复在消费每个目标作品前执行作品范围的同步与解析，schema 每次运行只检查一次，不调用全局 `SyncSelections("")` 或解析无关失效手选。当前调用已成功执行全量时复用其准备结果，额外同步为零。逐作品准备后以原前缀游标重新读取现有有界 dirty 页，只刷新同一 work 的 revision；目标已消失或被新前缀挤出探测页时不确认旧版本，继续推进原游标，遗留项由最终 CAS 拒绝完成并留待下次。
- 每次运行最多消费 1,000 页，现有 DAO 每页至多 100 个作品；达到上限且仍有待办返回 `ErrShareExportChanged`，不假成功、不重复全量，下次运行恢复。源/配置/dirty CAS、计划键、失败重试与 `FinishBaseline` 的全队列检查保持原样。并发进入已过游标前缀的变更留给下次运行，不能被本轮成功确认。
- 每十个尝试作品、页末及取消/失败退出均持久化 `processed_works`、`consumed_works`、`round_consumed_works`、`failed_works`、游标、轮数与待办状态；`round_consumed_works` 是当前 dirty 页已成功确认的数量，页内小批报告不累加到新轮，最终收尾保留末轮数量，空队列为零，事件与 metadata 均包含该字段。剩余量复用 `DirtyBatch("")` 的至多 100 项探测：`pending_works_exact=true` 为当前查询准确值；满页时为至少 100 项，下界标志为 false，绝不伪装成完整 COUNT。取消后的收尾最多五秒。成功确认后 phase 写 `completed`；失败、取消、CAS/页数上限分别写 `failed`、`cancelled`、`pending`。进度/探测失败不能再写 completed；探测失败显式标记 `pending_probe_failed=true` 与 `pending_works_exact=false`，metadata 写失败只做有界失败状态重试并返回错误，Redis 不可用时不能保证新状态落库。
- 来源一致性：逐作品准备前后的 `ObserveWork` 比较来源集合、身份、文件/分享版本、可用/取消状态、季集签名；读取待写来源再次核对身份、版本与签名；active 来源必须取得输出键，空/不完整结果不能确认；持久选择消费在 `CompleteWork` 前重读观察并核对。复用全量准备不等于信任旧选择：既有 ResolveSelection 的 live 归属/可用性/季集校验、锁内来源版本复读、selection receipt revision 检查继续生效，之后仍须当前来源观察与 dirty/config/输出快照 CAS。没有全库跨文件系统事务：变化后可以安全生成当前有效输出，也可能部分落盘后失败；计划键持久保留供重试，最终观察至事务提交间仍依赖业务变更触发 dirty revision。绕过触发器的外部直接写入不在保证范围。

### 模板与接线


以上时间、标识及业务 ID 均为合成示例。时间按进程时区输出 RFC3339、固定三位毫秒，UTC 表示为 Z；不改进程 TZ。无上下文 request_id/task_id/trace_id 统一为 `-`；HTTP 派生上下文共享原子 seq，区分同请求各行而非保证日志交付恰好一次。JSON 字段对象和错误链数组保持稳定；最多 32 项错误与 16 层嵌套。两种格式均转义换行/控制字符，禁止伪造物理行。

- 新调用使用 `logger.WithContext(ctx, "业务模块").Log(level, message, logger.Fields{...}, err)`。统一 HTTPContext 在无上游标识时使用 crypto/rand 支撑的 UUIDv7；合法 `X-Request-ID` 优先沿用，其次有效 traceparent 的 trace-id，非法/过长值重新生成；上游自己重复 ID 时不会偷偷换号。X-Trace-Id 单独绑定用户动作。UUIDv7 有时间顺序与随机位，跨进程不依赖共享计数；随机碰撞概率极低而非数学上绝对不可能（当前 google/uuid 实现保留 62 个密码学随机位，另含时间/亚毫秒序列位）。运行测试不能证明普适唯一性。
- 保留 `Debug/Debugf/Info/Infof/Warn/Warnf/Error/Errorf` 格式化 API；主程序旧 API 委托同一日志核心。旧调用未显式传入上下文时不解析消息内的 ID 来冒充关联；`module` 从调用文件推导，`error` 参数仍产生错误链。
- `SetOutputs`、`SetLevel`、`SetFormat` 与写入共用锁，保留日志文件分流与现有读取接口。nil writer 丢弃，输出失败使用固定人类模板且 req=-；调用方负责 writer 生命周期、禁止字段并发修改和 writer 重入。legacy 格式化入口仍缺少 ctx 时明确 req=-，不从消息猜测标识；新请求代码必须传 ctx，不能因某条兼容调用出现 req=- 而宣称全仓旧 API 已全部上下文化。
- 启动不再用 `gin.Default()` 的原始 URL 日志与请求转储恢复器，改为仅记录路由模板、方法、状态、耗时的中间件。恢复日志只记录 panic 类型，不记录 panic 值、请求头或请求体。标准库/Gin/HTTP server 日志旁路使用 `logger.Writer`：省略不可控的全部原始文本，只记录来源与字节数；代价是这些外部日志不再保留详细诊断文本。

## STRM 播放记录元数据超时降级（2026-09-27，维护者：Codex）

## 直链调用来源日志（2026-09-23，维护者：Codex）

## Emby 实例反代与 STRM 浏览器中继 / 原生 302 播放（2026-10-12，维护者：Codex）

每个实例通过 `proxy_port` 独立监听，启动和 CRUD 使用同一 `EmbyProxyService`，在互斥区内保留绑定端口直至持久化结束；失败释放新端口，原监听保持。v41 迁移增加非空默认值 0、范围约束及非零端口唯一索引。普通请求使用标准库 `httputil.ReverseProxy`；直接播放请求通过上游 `PlaybackInfo` 获取 HTTP(S) STRM 地址，有非空 `Origin` 时中继媒体字节，无 `Origin` 时继续返回 302 且不获取媒体。旧通用重定向接口及 Nginx 路由已删除。

回归覆盖 GET/HEAD 302 且不请求视频、Range/Cookie/认证/查询参数/请求体透传、子路径、多版本媒体源选择、已确认非 STRM 媒体的直接播放/转码/HLS 回源、解析/上游/授权错误、WebSocket 升级及停止、监听器启动/停用/改端口/删除/关闭、冲突及持久化失败回滚；DAO 和 Controller 测试验证端口字段读写、任务记录和参数拒绝。前端脚本 `node scripts/e2e-emby-proxy-port.mjs` 使用模拟接口验证真实弹窗回显、保存、空端口归零和 Docker 提示，不连接真实 Emby。

STRM 禁止回源修复先补复现：成功 302 后请求转码/HLS，以及 `PlaybackInfo` 变成本地缓存路径但 `/Items` 仍为 `.strm`。断言返回 502、有 ERROR 日志且视频回源调用次数为零。播放入口识别与转码判断分离，覆盖 stream 各扩展名、original、HLS 清单/分片和原始下载；只有确认非 STRM 才调用透明反代。额外覆盖无效 URL、缺失或不匹配媒体源、未知项目类型、JSON 错误、401/403、异常上游状态、超时和取消。有效直接播放可在下一次请求恢复 302，不保留永久禁用状态。

失败日志复用现有 logger 与请求上下文；测试验证实例/端口/媒体/来源/阶段/状态/耗时字段、响应 `X-Request-ID`、每次失败只有一条主要日志及敏感信息脱敏。普通登录、浏览、图片、字幕保持透明反代，正常响应的请求标识不会被上游覆盖或重复追加。无 `Origin` 的 GET/HEAD 302 均不会探测目标，客户端收到 302 后的直链故障仅在再次请求反代时才能被观察。监听器主动关闭产生的 `net.ErrClosed` 不记录为监听失败。

浏览器中继使用独立无整请求超时的客户端，DNS/拨号/TLS/响应头有界，闲置连接随服务关闭释放；客户端取消或服务关闭会中断传输。每跳保留 GET/HEAD、Range、If-Range、Accept、User-Agent 和条件校验头，不复制 Cookie、Authorization、Emby Token、Origin、Referer 或客户端查询凭据。最多跟随五次 HTTP(S) 重定向，支持相对地址；首地址及每跳全部 DNS 答案均按 allowed 规则校验，允许公网、RFC1918、回环、CGNAT、IPv6 ULA 和公网/私网混合答案，不设 own-host 白名单。允许内网/回环地址是刻意设计——内网分域 DNS 会把本服务的公网域名解析到局域网地址，用于节省 CDN 流量，中继必须照走。拒绝无效 IP、zone、0/8、未指定、255.255.255.255、组播和链路本地地址，IPv4 映射地址先校验 zone 再解映射。拨号固定已验证 IP，TLS 验证原域名，不经环境代理或二次 DNS 解析。200/206/416 及媒体头保留，正文通过 `io.Copy` 流式传输；响应头前失败使用统一可读错误，响应头后读写失败只记录既有脱敏日志并正常返回、关闭上游正文，不 panic、不追加错误正文、不改写状态码。媒体源选择和 STRM 禁止转码/HLS 回退规则未改变。

审查修正（2026-10-12，维护者：Codex）：响应头一旦发送，不能再替换为可读错误响应。已知 `Content-Length` 时，客户端可通过实际收到的字节不足识别截断；未知长度的流在处理函数正常返回后可能呈现正常完成，若不主动中止传输层，就无法无歧义地通知客户端流失败。本实现不使用 panic 或连接劫持来中止传输。流错误回归直接调用处理函数，不再捕获并接受 `http.ErrAbortHandler`，覆盖已知/未知长度的上游读失败、下游写失败以及取消/关闭后的正常返回；响应头前 GET/HEAD 可读失败机制保持不变。

共同 CORS helper 覆盖中继、302、统一失败的 GET/HEAD 分支和请求标识失败的 503 分支：仅非空 `Origin` 回显来源、允许凭据并暴露 Content-Range/Length、Accept-Ranges、Content-Type，追加 Vary Origin 而保留已有 Vary。所有 OPTIONS 请求在访问上游前本地返回 204；有 Origin 时声明 GET/HEAD/OPTIONS 及 Range、认证等允许头，无 Origin 不新增 CORS 头。
