## STRM 定时并发与资源等待（2026-09-28，维护者：Codex）

全量生成和增量同步在输出目录被占用时重试获取目录树锁，重试前释放本轮已取得的祖先锁和连接；只重试明确的目录占用错误，数据库错误直接返回。配置页生成、任务恢复遇到配置占用也等待。配置锁与目录锁的总等待上限为 30 分钟，等待期间检查取消标记。互不重叠的目录继续并行，同一调度或同一配置的重复定时触发仍保留跳过记录。

回归用例覆盖两个不同配置的定时任务同时进入处理器、配置释放后继续、已取消任务不获取空闲锁、目录锁失败后释放并重试、等待超时及数据库错误不重试。验证命令：`go test ./...`、`npm run build`。测试使用 sqlmock 和 miniredis，不访问真实网盘或修改媒体目录。

## 分享删除与 STRM 清理（2026-09-27，维护者：Codex）

分享管理的“删除”先弹出二次确认，明确同步文件记录、STRM 数据库记录和磁盘 STRM 的清理范围。取消不发送请求，删除失败保留弹窗以便重试；成功刷新列表并移除选中项。网盘原文件不受影响。

Service 与同步、识别及分享导出任务互斥。按分享码获取持久播放映射，结合当前导出状态、历史路径和旧文件清单检查 STRM 内容，删除匹配播放映射的文件；不递归删除目录，不删除其他播放地址的文件。缺失文件允许继续清理。历史路径删除前持久登记归属，磁盘部分失败或后续数据库事务失败时保留分享记录，重试可继续清理。数据库事务统一删除播放映射、导出清单、分享记录，并通过级联删除同步文件及季集记录，只回收不再被引用的媒体主数据。

验证：`go test ./...`、`npm run build`、`node scripts/e2e-share-delete.mjs`（模拟 API；可用 `E2E_BASE_URL` 指定前端地址）。新增 Service 测试覆盖任务互斥、目标文件隔离、目录拒绝、历史文件清理后数据库失败重试及未导出分享；DAO 测试覆盖事务回滚；Controller 测试覆盖参数、成功及失败响应。

## STRM 播放记录元数据超时降级（2026-09-27，维护者：Codex）

实库只读诊断确认：完整导出快照也执行历史映射关联查询，单条元数据查询耗时约 6.2 秒，超过两秒预算。DAO 改为先按主键读取快照，标题和海报完整时直接返回文件级季集；同一映射复测约 1.6 毫秒。旧映射缺少展示字段时仍走兼容关联查询；关联失败时保留已读取的快照信息。`TestSharePlaybackMetadataUsesEntrySnapshot` 要求完整快照只查询映射表，`TestSharePlaybackMetadataLegacyFallback` 覆盖历史映射兼容。

分享与普通 STRM 的元数据查询和播放记录写入各自使用独立的两秒超时。元数据查询超时后，分享入口使用映射 ID、普通入口使用文件名作为降级标题，仍尝试保存播放记录；数据库写入失败仍释放会话去重标记，允许后续请求重试。查询和保存连续执行，最坏耗时预算为四秒。

`TestPlaybackRecordSurvivesMetadataTimeout` 模拟元数据查询耗尽上下文，并要求保存时上下文有效，覆盖分享与普通入口；修复前两种入口均保存零条记录，修复后保留标题、直链、来源 IP 和请求方法。没有历史记录的播放无法通过本次修改自动补回。

## 直链调用来源日志（2026-09-23，维护者：Codex）

搜索 INFO 日志中的 `[DirectLink]`：`event=request` 记录服务端生成的 `request_id`、入口 `source`、方法、URL 路径、客户端 IP、网络对端地址、UA、Range 及资源标识；`event=resolve` 记录实际请求 115 的账号、pickcode 和生效 UA；`event=complete` 记录相同请求 ID、HTTP 状态码和总耗时。响应头同步返回 `X-Request-ID`。`source` 分别为 `strm_playback`（普通 STRM）、`share_strm_playback`（分享 STRM）、`cloud115_api`（115 直链接口）。先按资源标识找到重复请求，再按请求 ID 关联阶段，结合 IP、UA 和 HEAD/GET 判断调用来源；UA 是客户端自报信息，代理后的客户端 IP 取决于 Gin 的可信代理配置。

日志不记录完整查询串、Cookie、Authorization 或签名下载地址；旧底层开始/成功日志降为 DEBUG。回归测试 `TestDirectLinkRequestLogsIdentifyCallerWithoutSecrets` 覆盖 HEAD、GET、失败返回、独立请求 ID 和敏感字段排除。此变更仅增加诊断信息，不改变直链获取次数；部署新版后才能观察新日志。

## STRM 播放会话去重（2026-09-13，维护者：Codex）

运行版本回归：前端 Vite 更新不代表 Go 后端已更新。此次重复记录复查发现，8082 实际运行的 `debug/easy-strm-library-fix.exe` 编译于 11:58，而去重代码修改于 12:11。`start.bat` 现先编译当前源码到临时 exe，成功后替换并启动 `debug/easy-strm-dev.exe`；`restart.bat` 复用此流程，编译失败保留原服务。验收需核对监听端口的进程路径及编译时间，不能仅凭前端提示判断修复已生效。

`TestDirectLinkRepeatedRequestsPersistOneRecord` 联动真实控制器、Service 与 sqlmock DAO，验证 12 次 HEAD/GET 返回不同 CDN 地址时只写入一条记录。历史记录不自动删除；当前去重状态保存在进程内，重启会重新建立会话。同一代理 IP 下的客户端无法仅凭 IP 区分，五分钟规则是解析会话近似值，并非精确观看次数。

普通与分享 STRM 的成功 GET/HEAD 解析仍会触发播放记录入口，但 Service 会按“资源稳定标识 + 来源 IP”合并连续调用；同一组合每次重复解析都会延长会话，静默超过 5 分钟后再次访问才新增记录。该规则用于吸收 Emby/Jellyfin 对 115 临时 CDN 地址的预解析、重试和刷新，不会把不同文件或不同来源合并。

后端回归测试覆盖同会话 HEAD/GET 合并、不同文件、不同来源、超时后重播、并发请求及首次保存失败后重试。前端播放记录抽屉同步说明展示的是播放会话，而不是原始直链请求数。
