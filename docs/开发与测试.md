# 开发与测试

- 更新日期：2026-08-30
- 维护者：Codex

## 1. 当前开发基线

项目采用 Go 后端与 Vue 3 前端：

- 后端：Gin、PostgreSQL、Redis。
- 前端：Vue 3、Vite、Naive UI、Tailwind CSS。
- 自动化：Go test、Go vet、Vite build、Playwright 脚本。

修改代码时应保持 Controller、Service、DAO、Domain 的依赖方向；页面统一通过 `src/utils/api` 调用后端。

仪表盘账号容量使用 `easy_strm:dashboard:account_quota:<账号ID>` Redis 键，固定 TTL 为五分钟。Service 必须先读缓存，未命中、过期或损坏时再调用115接口并回填；Redis 故障只能降级为实时查询，不能阻断仪表盘。

## 4. 2026-08-05 115 云下载

本轮新增 115 云下载（离线下载）能力，支持一次提交多条 ed2k、magnet、http/https、ftp 链接。

2026-08-18 更新：超过 100 条的输入不再由前后端拒绝。入口校验账号和链接后立即创建任务中心任务，后端单工作队列按 `100 / 100 / ... / 余数` 顺序调用 115；100 条及以下继续沿用同步提交与逐链接受理结果。回归测试 `TestOfflineDownloadSubmitLargeBatchQueuesAndChunks` 使用 201 条链接验证入口不会等待115调用，并验证实际批次为 `100 / 100 / 1`。

变更范围：

- 后端：新增 `OfflineDownloadController`、`OfflineDownloadService`、`OfflineDownloadTaskDAO` 与 `domain.OfflineDownloadTask`，路由在 `auth.go` 统一注册；`115_offline.go` 封装 115driver 的离线下载增删查接口。
- 接口：
  - `POST /v1/resource/115-offline/submit`：提交链接（`cloud115_id`、`urls`、可选 `target_dir`），返回任务中心任务 ID 与逐链接受理结果。
  - `GET /v1/resource/115-offline/tasks`：按账号、状态分页查询记录。
  - `DELETE /v1/resource/115-offline/tasks/:id`：删除记录，`delete_files=true` 时同时删除 115 侧任务与已下载文件。
- 数据库：迁移 `migrate_v15_offline_download_task.sql` 创建 `t_offline_download_task`。
- 前端：新增 `src/views/resources/OfflineDownload.vue` 与 `src/utils/api/offline.js`，作为资源聚合页第二页签接入；`TaskCard.vue` 支持 `offline_download` 任务类型展示。

关键实现约束（回归时重点关注）：

- 115 批量离线接口遇到重复/无效链接时会整体拒绝，且响应错误码字段为 `errcode` 而非 `errno`，115driver 无法映射为哨兵错误，错误体为加密串。Service 层通过 `isOfflineDuplicateErr`、`isOfflineInvalidLinkErr`、`isOfflineQuotaErr` 做字符串识别，命中重复/无效时降级为逐链接提交，配额/登录类致命错误直接归一化返回。
- 链接已存在离线任务时按 URL 精确匹配、再按提取的 hash 兜底关联现有任务，不重复提交。
- 相关单测必须使用与生产响应形态一致的错误样本（含 `"errcode":10008` 加密体），不能只测哨兵错误。

## 9. 文件名识别规则开发约定

- 规则配置以 `filename_recognition_rules` 配置键存储在 `t_system_config`，不新增独立配置表；未配置或历史配置无效时使用代码内置模板。
- 正则针对标准化文件名执行：先去除扩展名，将点号、下划线和连字符转换为空格，再合并连续空白。
- 所有规则必须包含 `(?P<title>...)`；剧集规则必须包含 `(?P<episode>...)`，可选 `(?P<season>...)`，没有季捕获组时使用 `default_season`。
- 保存前必须覆盖正则编译失败、重复 ID、错误媒体类型、缺少捕获组、示例不匹配、全规则禁用等失败分支。
- 测试接口与整理服务必须统一调用 `TmdbService.ParseFilename`，不得在 Controller 或前端复制文件名业务规则。

## 11. Telegram 115 资源操作开发约定

- 更新日期：2026-08-30
- 维护者：Codex

- 文本解析、账号决策和任务提交集中在 `TelegramResourceService`，机器人生命周期服务只负责授权、异步调度和卡片回写。
- 分享链接优先于普通 HTTPS 云下载链接识别，避免115分享被误提交为离线下载。
- Telegram 与企业微信回调复用多行解析：以非空行为任务边界，每行独立应用 `链接 [账号名称] [/目标目录]` 语法并创建任务；批量执行必须在单行失败后继续，并汇总各行任务 ID 或失败原因。
- 多行回归测试至少覆盖全部成功、部分失败继续执行、逐行目录、企业微信纯文本和 Telegram HTML 汇总内容；单行命令格式必须保持兼容。
- 账号优先级数字越大越优先；同优先级必须以较小账号 ID 决胜，保证选择稳定。
- 分享密码使用标准 URL Query 解析，不能把空 Fragment 标记 `#` 计入密码。
- 新增语法或账号规则时至少覆盖链接、链接加目录、链接加账号、链接加账号和目录、默认账号排序、指定账号以及提交参数回传。

## 12. 媒体源监控开发与测试约定

- 更新日期：2026-08-30
- 维护者：Codex

- 媒体源只有在 `enabled=true` 且 `watch_enabled=true` 时才允许启动监控；前端状态文案和统计必须同时遵循这两个字段。
- 列表接口必须使用 WatchService 当前进程状态填充 `watch_running`；配置已开启但启动失败时显示“监控未运行”，不得显示为运行中。
- 新建媒体源未显式传递 `enabled` 时默认启用，编辑页面必须保留独立的启用/停用开关。
- 本地监控必须为已有子目录注册 fsnotify，并在新增目录进入时递归注册其目录树、发现其中视频文件。
- 115 监控必须完整分页并递归扫描监控目录；初始快照读取失败时不得以空快照启动，避免下次轮询误把历史文件当作新增文件。
- 回归测试至少覆盖创建默认启用、本地嵌套目录、115 子目录和超过单页上限的文件列表。

## 13. 网络代理开发与测试约定

- 更新日期：2026-08-30
- 维护者：Codex

- 配置有效的代理服务器地址后，Telegram、GitHub、TMDB 域名默认走代理，不依赖 `proxy_domains` 配置。
- `proxy_domains` 仅用于追加自定义站点，不得覆盖或关闭内置代理站点。
- 未配置代理服务器地址时所有请求保持直连；内置域名规则本身不得隐式启用代理。
- 网络探测和 TMDB、Telegram 等真实业务请求必须复用同一代理感知 HTTP 客户端规则。
- TMDB 网络探测必须动态读取已保存的 `tmdb_api_key` 并仅附加到实际请求；响应地址和错误信息不得包含明文 Key。
- 回归测试至少覆盖内置域名、非内置域名、自定义域名追加和业务客户端注入。
