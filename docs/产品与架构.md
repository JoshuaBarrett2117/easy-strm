# 产品与架构

## 配置明文查看（2026-09-23，维护者：Codex）

TMDB API Key、全局 API Key、Telegram Bot Token、企业微信 Secret / Callback Token / EncodingAESKey、AI 辅助识别密钥、Emby 实例密钥和 AI 图片接口密钥均支持点击输入框眼睛查看已保存的完整值，再次点击隐藏。输入了新值时查看当前输入；仅查看已保存值不会修改表单，留空保存仍保留旧配置。MetaTube Token 和基础 Emby 配置继续使用已有的密码显示切换。

普通配置读取接口保持脱敏；明文通过登录后的 `/settings/secrets/:key` 按字段白名单读取，Emby 明文通过 `/emby/secrets/:key` 复用管理员权限，实例密钥还需有效 `server_id`。响应禁止缓存。关闭弹窗、切换实例或重载配置会清除显示状态，过期请求不会覆盖当前界面。此功能用于可恢复的配置凭据，不改变用户登录密码的存储方式。

## 分享作品识别与季集复用（2026-09-23，维护者：Codex）

分享识别复用通用文件名规则，明确的罗马部数按季号解释：`妙手仁心Ⅰ-31.mkv` 对应 S01E31，`妙手仁心Ⅱ-01.mkv` 对应 S02E01；查询名均为“妙手仁心”，跨季共享同一个 TMDB 剧集身份。支持 Unicode 罗马数字及 I–XII 的 ASCII 写法。普通 `标题-01` 需要明确电视剧类型、剧集目录上下文，或同目录同标题同时存在 01、02 连续编号，才推断为单集；原始文件名和网盘路径不修改。

任务按分享、目录上下文、规范化标题、年份、类型及元数据策略复用作品身份，纯 Season/Sxx 季目录不拆分作品。同组并发请求合并，季集号始终逐文件保留；已落库身份只有通过当前标题、年份和类型核验才用于新集，历史身份相互冲突时保留待确认。Redis 作品缓存使用独立 v1 命名空间与规则配置指纹，有效期七天；缓存中心 TMDB 缓存组包含这些键。普通任务复用已识别文件和作品，显式重新识别绕过作品缓存及 TMDB 搜索缓存，手动修正使相关作品缓存失效。

常规识别无匹配后才允许 AI 辅助，同一任务每作品最多调用一次，AI 建议仍需通过数据源核验，不能覆盖已明确的 tv/movie 类型或文件季集。网络和别名接口故障不作为内容无匹配触发 AI，也不持久缓存为失败身份。失败结果不补详情；成功结果按作品补元数据，并使用剧集详情中的季目录核对季号。对应季缺失或详情不可用时保留作品 ID 与解析季号，在分享文件“识别说明”中显示“季信息待核对”，不改查电影。

## 分享同步与识别并行（2026-09-22，维护者：Codex）

分享文件同步与媒体识别可同时运行，页面分别跟踪所有活动分享任务。识别只处理任务加载时已入库的候选，新同步文件可通过“继续识别待识别内容”处理。

同一组分享的重复同步请求（含乱序或重复 ID）在任务运行期间返回相同任务 ID；不同组的同步仍串行，避免并发扫描账号。任务结束后允许重新扫描。同步以分享及远端文件 ID 匹配已有记录，无远端 ID 时按路径匹配，不重复建档，不清除未变化文件的识别结果和季集关联，也不递增其识别版本。SHA1 确认变化时重置识别，路径变化时递增版本以阻止旧路径识别结果覆盖。扫描时间仍正常刷新。清空文件记录与同步、识别保持互斥。


## 播放记录缺失电影海报补全（2026-09-13，维护者：Codex）

打开播放记录时，缺少海报且保留视频文件名的电影在后台调用已配置的 TMDB 搜索；仅在年份一致、片名匹配且电影 ID 唯一时补齐该记录的空海报。最多并行两项，每项限时 20 秒，失败十分钟后可重试。结果持久化并在下一次列表刷新显示，历史记录同样适用；不在直链播放请求中调用外部元数据服务。没有年份、匹配有歧义或剧集文件不使用此电影回退。

## 播放记录季集展示（2026-09-13，维护者：Codex）

新播放记录的标题包含文件级季集，例如“龙珠 · 第 2 季 · 第 3 集”。普通 STRM 从识别缓存读取季集，仅电视剧附加标签；分享 STRM 优先使用导出映射的季集快照，旧导出映射按分享和具体文件关联本地季集表。支持第 0 季特别篇及多集合一文件；无法确定时不猜测。格式化标题沿用播放记录的 `name` 字段持久化，前端允许换行。历史播放记录缺少文件身份，不能仅凭同名作品补写季集，保持原样。

## STRM 共存与增量输出（2026-09-12，Codex）

115 全量生成默认保留目录内容，手动弹窗或定时任务的 `clear_before_generate` 可显式选择清空全部内容。源目录解析失败不清空。勾选清空会影响同目录的分享 STRM、字幕及图片，操作无法回滚。

分享库新增 `share_strm_incremental_export` 调度处理器，使用现有分享导出设置；不自动创建调度。每次分页检查有效已识别来源，对输出内容核对后增量写入，缺失文件补回，无变化文件不重写。完整无筛选检查成功才标记旧导出失效，默认保留文件。

v34 新增导出状态、路径历史和清理阶段表。运行时按操作系统归一化历史清单路径。115 与分享输出通过目录树 PostgreSQL 共享/独占锁协调，其他来源及未登记的现存文件报告冲突。普通与分享同目录可共存，但相同输出路径不互相覆盖。

## 分享文件与媒体主数据（2026-09-12，维护者：Codex）

分享处理拆为两个独立任务。`POST /media/share-records/:id/sync` 递归解析完整分享目录，只把真实视频文件同步到 `t_share_media_file`；每次完整扫描使用唯一标记 upsert 文件并在成功结束后标记未出现的旧文件为失效，解析失败、超时或脱敏目录不会误删或伪造文件记录。文件优先按分享 ID 与 115 文件 ID 去重，没有远端 ID 时才按完整相对路径去重。

`POST /media/share-records/:id/identify` 只读取已落库且有效的文件，不再隐式扫描分享。匹配成功后按“元数据来源、提供方、媒体类型、外部 ID”全局 upsert `t_share_media`，不同分享、季和集共用同一媒体主记录；未匹配文件只更新文件状态和错误，不创建媒体主数据。电视剧必须具备季集信息，`S01E01E02` 等多集文件在 `t_share_media_file_episode` 保存多行映射，手动识别也必须同时提交有效季集。

资源库直接读取全局媒体主表，并通过有效文件统计分享来源数和文件数。文件级接口 `GET /media/share-records/:id/files` 返回路径、有效状态、错误、媒体关联和季集映射；媒体海报接口按 `media_id` 聚合。STRM 只使用有效且已识别文件，电视剧以持久化季集映射为准，多集文件为每集生成一个入口并共同指向同一真实文件。数据库由 `migrate_v33_share_media_master.sql` 从已执行的 v32 迁移，脚本包含历史目录清理、全局身份去重、本地多集回填、唯一索引及上线校验。

## 分享资料库 STRM 导出与播放（2026-09-13，Codex）

分享资源库右上角「导出 STRM」可配置服务器导出目录、播放访问地址、已配置的 115 账号和网盘转存目录。导出范围为当前已应用筛选条件下的全部作品，不受页面页码限制；未标记取消且已识别的来源参与导出。导出在任务中心执行，可查看生成数量、失败详情和取消任务。

目录复用整理规则的分类匹配与分类路径拼接行为（取命中分类目标目录的最后一级），无匹配时使用 `movie` / `tv`。例如 `国产剧/作品 (2024) {tmdb-10}/Season 02/作品 - S02E03.strm`。电影为 `分类/片名 (年份) {tmdb-ID}/片名 (年份) {tmdb-ID}.strm`。季集使用当前文件名识别规则，支持特别篇第 0 季，以及 `Season 02/EP03.mkv`、`第2季/03.mkv`；单文件手动识别中明确保存的季集优先。不能确定集数的文件记录失败，其他可识别文件仍导出。同作品同集采用首个可导出的有效来源；重复导出更新同名文件，不清理历史目录。

STRM 内容为 `{播放访问地址}/share-strm/{稳定ID}`。扫描候选、待识别和失败状态保存在 `t_share_media_file`，只有识别成功的媒体信息才进入 `t_share_media`；两表通过可空的 `media_id` 关联。导出仅分页读取这两张本地表中的文件路径和已匹配结果（关联本地分享主表读取地址/提取码），不重新访问分享链接、不请求 TMDB、不转存视频。仅有目录、没有具体视频文件的记录会报告失败，不进行网络补扫。GET / HEAD 播放请求读取 PostgreSQL 播放映射，在配置的 115 目录下按 ID 建立独立子目录。首次播放缺少文件 ID 时，沿本地保存的相对路径逐级读取所在分享目录，定位具体视频并缓存 ID，不遍历无关目录；后续转存复用 ID。只转存对应的视频文件；数据库事务锁串行化同文件转存。已有同名视频直接复用，服务重启后仍可使用。直链按当前播放器的 User-Agent 获取，每次返回 302，不缓存临时签名链接；分享转存、账号、列表或直链失败返回明确错误。播放转存不会清理网盘文件。

分享 STRM 成功返回 302 后与普通 STRM 共用播放记录表，GET 与 HEAD 预解析均进入记录链路，失败请求不记录。播放器对同一资源的 HEAD/GET、重试及临时直链刷新按“资源稳定标识 + 来源 IP”归入同一播放会话；连续解析会延长会话，静默超过 5 分钟后再次访问才新增记录。导出映射同时快照媒体主数据 ID、标题和海报路径，记录时优先使用快照；旧映射则按分享码及文件 ID/路径回查 `t_share_media`，从而不依赖普通整理链路的文件名识别缓存。新播放记录会带入当前可用海报；分享历史记录因旧数据没有稳定分享映射 ID，不做可能串图的自动改写。

普通 STRM 的标题和海报来自 `t_identify_cache`。识别结果落库必须同时保存 `poster_path`；对于旧版本漏存的 TMDB 海报，启动迁移按媒体类型与 TMDB ID 从本地 `t_tmdb_cache` 回填，再按精确文件名哈希或唯一标题补齐历史播放记录。整个修复过程只使用本地数据，不在播放请求中发起 TMDB 网络访问；未识别文件或本地从未缓存过海报的媒体仍显示无海报。

配置复用系统配置表的 `share_strm_settings`，播放映射使用 `t_share_strm`，启动时执行内嵌的 `migrate_v29_share_strm.sql`。映射独立于分享管理记录，删除分享管理记录不会自动删除已导出的播放链接；播放仍依赖分享可转存或目标账号已存在对应视频。修改目标账号或网盘目录后，已有链接读取新设置；修改播放访问地址或导出目录后需重新导出。

部署时将导出目录挂载给 Emby / Jellyfin 等媒体服务器，并确保其能访问配置的播放地址。Docker 内路径须使用容器中的绝对路径；内置 Nginx 和 Vite 已代理 `/share-strm/`，使用自建反向代理时也需转发此路径到后端并保留 User-Agent、302 响应，预留首次转存耗时。此能力需要有效的 115 账号及分享；本地模拟测试不代表真实账号转存可用性。

## 1. 产品定位

`easy-strm` 是面向个人媒体库的文件整理与 `.strm` 生成工作台。产品聚焦高频、可直接操作的媒体处理流程，不承担下载器管理或完整媒体资产治理平台的职责；资源获取仅覆盖 115 分享转存与 115 云下载（离线下载），不接入资源搜索与 PT。

核心流程：

```text
媒体源接入
  -> 文件浏览与选择
  -> TMDB 自动或手动识别
  -> 重命名与整理预览
  -> 移动、复制或链接
  -> 可选元数据刮削
  -> STRM 生成
  -> Emby 刷新与任务追踪
```

## 2. 功能范围

### 2.1 媒体源与文件

- 本地目录与 115 云盘媒体源。
- 媒体源启停、排序、监控目录、整理目标、媒体类型和冲突策略。
- 文件分页浏览、搜索、筛选、面包屑导航与批量选择。
- 本地和 115 文件移动、复制、删除、重命名；本地支持硬链接和软链接。

### 2.2 识别、命名与整理

- TMDB 电影、电视剧搜索和详情查询；自动电影识别固定优先查询 TMDB，仅在成人模式和 MetaTube 均启用且 TMDB 无可用结果时回退本地 MetaTube，显式指定来源时不回退。整理中明确选择电影类型会跳过剧集文件名规则，避免字母番号被误判为动漫集数；剧集始终使用 TMDB。
- 文件名解析、自动识别、候选选择、手动修正和缓存回流。统一 `IdentifyWithAssist` 流程先执行规则与数据源查询，只在内容无匹配时允许 AI 给出标题、原名、年份和类型建议；AI 建议必须重新查询并通过标题、年份、类型及唯一身份核验。
- 独立识别测试页可模拟真实整理解析，展示标题、媒体类型、年份、画质、来源、编码以及剧集季数和集数，并可继续查询数据源候选；AI 辅助分析并列展示建议、调用场景、前后查询词、元数据来源和最终核验结论，全程不写缓存。
- 文件名识别规则以有序模板配置，内置 `S01E05`、`1x05`、`Season 1 Episode 5`、`第1季第5集`、`EP05`、电影年份等常用格式；保存后立即应用于测试页和整理链路。
- 电影与电视剧命名模板。
- 整理候选扫描、异步预览、预览恢复、冲突策略和失败项重试。
- 按 Genre、国家/地区、语言、年份和标题关键字配置分类策略。

### 2.3 刮削与 STRM

- 生成电影、剧集 NFO。
- 下载海报、背景图和剧照。
- STRM 配置增删改查、全量生成、任务进度和定时执行。
- 通过公开 `/direct-link` 接口解析 115 播放直链。
- 整理完成后可生成 STRM 并触发 Emby 刷新。

### 2.4 自动化与运维

- 本地目录实时监控、115 目录轮询与自动整理。
- 自动整理失败分类、取消和重试。
- 统一任务列表、详情、进度、结果与失败信息。
- Dashboard、日志、网络检测、Redis 缓存管理和系统配置。Dashboard 的115账号配额优先读取 Redis，未命中时查询115并回填，缓存五分钟过期。
- Emby 观影监控按实例展示实时会话、用户/媒体/客户端排行、小时趋势、用户热力图和最近入库；历史优先使用 Playback Reporting，异常时统一降级到 easy-strm 每 30 秒自采的数据。
- Emby 媒体库管理以封面卡片展示媒体库名称、中文类型标签和媒体文件数量；封面与数量由后端代理读取，页面不暴露 Emby API Key，也不展示媒体目录。
- Telegram、企业微信应用、Server 酱和 SMTP 通知后端。Telegram 支持单管理员私聊长轮询机器人，可查询系统概览、最近任务、定时任务和 Emby 状态，并直接执行任务取消/自动整理重试、定时任务运行和 Emby 刷新。
- Telegram 使用 HTML 富文本和内联按钮，企业微信自建应用使用 Markdown；所有已启用通知渠道均在任务触发时推送一次、任务进入完成/失败/取消终态时再推送一次。Telegram 与企业微信另支持 115 账号状态通知，并在 Redis 中维护按渠道独立的首次启用基线、任务事件和账号快照去重，通知失败不影响业务任务。
- 企业微信应用可配置 API 接收消息回调。公开回调使用企业微信 Token 签名、EncodingAESKey 解密、Corp ID 与 Agent ID 校验，不依赖系统 JWT；文本消息支持帮助、系统状态、最近任务以及 115 分享转存/云下载语法，回复仍通过企业微信应用消息 API 发送。
- Docker Compose 部署 PostgreSQL、Redis 和应用服务。

### 2.5 资源聚合与 115 云下载

资源聚合页承载 115 生态的资源获取能力，包含两个页签：

- **115 分享转存**：分享链接一键解析与批量转存。
- **115 云下载**（离线下载）：
  - 支持一次提交多条 ed2k、magnet、http/https、ftp 链接，自动去重、去空白并过滤不支持的协议。
  - 可选择 115 账号与保存目录，未指定目录时默认使用 `/云下载`。
  - 100 条及以下链接同步提交；超过 100 条时立即返回本地任务 ID，由后端单工作队列按每批最多 100 条顺序发送到 115，并在任务中心持续更新提交与下载状态。
  - 批量提交被 115 以「任务已存在/链接无效」整体拒绝时，自动降级为逐链接提交，精确标注每条链接的受理结果。
  - 链接已存在离线任务时不重复提交，而是关联现有任务并继续跟踪其状态。
  - 提交成功返回任务中心任务 ID，云下载任务可在任务中心查看进度与结果。
  - 后台跟踪协程轮询 115 离线任务状态，把记录推进到完成、失败或已移除等终态；115 侧配额不足、登录失效等错误归一化为可读提示。

## 9. Telegram 115 资源操作

- 更新日期：2026-08-30
- 维护者：Codex

管理员私聊可直接发送115分享链接或云下载链接。消息语法统一为 `链接 [账号名称] [/目标目录]`：账号和目录都可省略，也可单独指定；目录必须是以 `/` 开头的115绝对路径。

Telegram 与企业微信应用回调均支持在一条消息中按行提交多个资源操作。每个非空行独立使用上述语法、独立选择账号与目录并创建一个任务；某行失败不会阻断后续行。处理完成后统一返回总数、已创建数、失败数，以及每行任务 ID 或错误原因。

- 分享转存默认选择活跃资源号，按账号优先级降序、账号 ID 升序；未指定目录时使用该账号配置的默认转存目录。
- 云下载默认按 VIP 观影号、兼顾账号、资源号的类型顺序选择；同类型按账号优先级降序、账号 ID 升序；未指定目录时使用 `/云下载`。
- 指定账号名称时不应用默认账号类型限制，但账号必须处于活跃状态且具有可用登录态。
- 机器人只负责编排现有 `ShareTransferService` 与 `OfflineDownloadService`，提交后返回任务卡片；真正完成时由统一任务终态监控发送成功通知。

## 10. 媒体源监控与自动整理

- 更新日期：2026-08-30
- 维护者：Codex

媒体源的“启用”是监控和自动整理的总开关；只有媒体源已启用且目录监控已开启时，后台才会运行监听。文件工作台会结合 WatchService 的当前运行状态，明确区分“媒体源已停用”“未开启监控”“监控未运行”“仅监控”和“自动整理中”，不再仅凭保存的监控开关显示运行中。

### 自动混合类型与 AI 辅助识别（2026-09-08，维护者：Codex）

分享管理“识别任务设置”配置扫描与识别合计的总时限，支持无限制（0，默认）或1–43200分钟。配置保存在系统配置表share_identify_timeout_minutes，新任务启动时读取，运行中任务不追随更改。无限制仍可通过任务中心取消，各外部接口保留自身请求超时。达到自定义时限明确提示分钟数，不再与分享取消混淆。接口GET/PUT /media/share-task-settings使用timeout_minutes字段。

批量识别遇到网盘明确取消的分享时，保存取消标签并跳过该分享及其历史媒体，继续下一条；任务展示已跳过取消分享数量。全部分享取消时正常完成，不按无媒体报错。任务超时和密码错误不作为分享取消处理。

新分享默认按单条媒体自动判断类型，编辑支持自动（混合）、电影、电视剧。历史显式类型不会批量覆盖。分享识别从原始路径派生中文名、英文名及年份，不修改文件名或网盘数据；排除集合目录查询，避免将剧集全集光盘按电影检索。候选须满足规范化标题或原名一致、年份相差不超过一年；同名同年的不同身份不自动选定。

分享识别绕过旧文件匹配缓存，保留TMDB搜索和详情缓存。单条分享“识别”和媒体“重新识别”会重新核验已有内容。扫描候选按分享与完整路径事务幂等写入，任务按路径去重，已被剧集目录覆盖的单集和剧集分碟不新增。历史重复记录不自动删除，可清空后重建。任务优先待识别、其次失败、最后已识别；总时限由识别任务设置控制，默认无限制；中断后可重新发起继续处理待识别项。同一后端实例只允许一个分享识别任务运行。

AI配置页位于 `/dashboard/ai-recognition`，统一服务接入分享识别、整理预览、自动监控整理、历史识别失败重试、手动识别预填、识别测试和无缓存刮削补全。支持OpenAI兼容接口根地址（例如含/v1）、API Key、模型、超时、提示词及场景开关。使用GET /models获取模型，POST /chat/completions发送messages、model和stream=false；不强制response_format以适配兼容端点。保存过连接信息后进入页面自动获取模型，也支持手动获取或填写模型ID；模型是否支持聊天需用测试按钮确认。

AI默认关闭；首次配置默认勾选复杂标题和常规无可靠匹配，类型不确定需显式开启。每条媒体每轮最多一次AI调用；输出仅作为片名、原名、年份和类型建议，仍经媒体数据库核验。手动弹窗的 AI 解析只预填表单，必须选择数据源候选后才能应用。刮削详情、ID、图片和 NFO 内容只来自 TMDB、MetaTube 或已有缓存。播放请求永不调用 AI。AI故障不影响普通识别；无可靠匹配不标成功。启用后原始路径会发送至配置端点。

配置以ai_recognition JSON复用系统配置表，专用接口原子保存和热更新：GET/PUT /settings/ai-recognition、POST /settings/ai-recognition/models、POST /settings/ai-recognition/test。公开响应不返回已存密钥；地址未变时空密钥保留，更换地址不自动携带原密钥。原始路径及已存分享内容不因此改变。

协议参考地址：https://platform.openai.com/docs/api-reference/chat/create 、https://platform.openai.com/docs/api-reference/models/list 。本次官方页面返回403，兼容行为通过本地模拟端点验证，未核验真实AI供应商。

# 全局第三方 API（2026-08-30，Codex）

系统提供全局 API Key 配置，第三方通过 `X-API-Key`（或 `Authorization: ApiKey`）直接调用现有业务路由，无需复制路由树。API Key 仅由专用接口管理，通用设置接口不会返回或修改密钥。企业微信回调仍使用自身签名校验，回调 URL 根据全局外部 API 地址生成。

同时提供 `POST /mcp` MCP JSON-RPC 入口。AI Agent 使用同一全局 API Key 完成 `initialize`、`tools/list` 和 `tools/call`，协议版本保持 `2024-11-05`。原有核心工具继续通过 typed registry 直接复用 Service。除核心 typed 工具外，启动装配会将正式注册的业务 HTTP 路由自动映射为 MCP 工具，参数按 path/query/body/file schema 传递，调用重新经过原 Gin 鉴权、参数校验和 Service；写入、删除及任务控制工具要求 `confirm=true`，文件上传使用 Base64，二进制响应也会编码为 Base64。

截至 2026-09-20，MCP 核心目录包含 26 个核心工具，并新增规则读写工具：`filename_recognition_rules_get`、`filename_recognition_rules_validate_samples`、`filename_recognition_rules_save`、`filename_recognition_rules_reset`、`media_categories_list`、`media_category_create`、`media_category_update`、`media_category_delete`、`rename_presets_list`、`rename_preset_get`、`rename_preset_create`、`rename_preset_update`、`rename_preset_delete`、`organize_rule_settings_get`、`organize_rule_settings_update`、`scrape_rule_settings_get`、`scrape_rule_settings_update`。核心目录包含 26 个工具：`system_status`、`tasks_recent`、`task_get`、`task_cancel`、`task_resume`、`media_sources_list`、`media_source_get`、`media_source_files_browse`、`media_source_delete`、`file_manager_locations`、`file_manager_browse`、`tmdb_filename_parse`、`tmdb_search`、`tmdb_detail`、`tmdb_identify`、`rename_preview`、`organize_candidates`、`strm_configs_list`、`strm_config_get`、`cloud115_accounts_list`、`cloud115_account_get`、`cron_tasks_list`、`cron_task_get`、`emby_status`、`emby_libraries`、`emby_refresh`。`tools/list` 对每个工具返回中文描述、封闭 JSON Schema 以及 `readOnlyHint`、`destructiveHint`、`idempotentHint` 标注。

2026-09-21 更新，维护者：Codex。鉴权兼容 `X-API-Key` 和 `Authorization: ApiKey <key>`。全部已注册 HTTP 接口（排除 MCP 自身）各自提供一个 `api_<method>_<path>_<摘要>` 工具，覆盖账号、配置、文件操作、整理执行、分享库、离线下载、通知和 Emby 管理。工具名最长 64 字符，通过 `tools/list` 查看准确名称。新增 HTTP 路由在启动装配时自动进入目录，保留原接口响应内容（包括原接口允许返回的凭据），原有核心工具仍保持其脱敏行为。MCP 使用全局 API Key，受保护业务路由沿用 API Key 对应管理员身份和原权限校验；公开接口也仍需先通过 MCP API Key 校验。

调用参数示例：`{"path":{"id":"7"},"query":{"limit":"20"},"body":{"name":"示例"},"confirm":true}`。路径变量和查询值传字符串，重复查询参数可传字符串数组；`body` 使用原 HTTP 接口 JSON 契约，业务字段校验仍由原 Controller 执行。上传使用 `file: {name, data}`（data 为 Base64），不能同时传 body。返回文本中的 JSON 包含 `status`、`content_type`、`body` 或 `base64`；重定向提供 `location`，HTTP 4xx/5xx 对应 MCP `isError=true`。所有非 GET/HEAD 工具需要 `confirm=true`，缺省只返回 confirmation_required。接口创建异步任务时原样返回任务 ID，继续使用任务查询/取消工具追踪。

### 分享目录脱敏统计（2026-09-08，维护者：Codex）
分享扫描遇到目录名中的连续半角或全角星号时，跳过该目录及其子目录，不发起媒体识别。分享管理媒体统计显示已识别、失败、待识别、脱敏，总数包含脱敏项。历史已保存的脱敏项刷新列表后单独归类；此前扫描时已被丢弃的目录需要重新点击分享的识别按钮补齐统计。同名脱敏目录按目录数量计数，重复扫描不累加。全部媒体已脱敏时识别任务正常完成。

### 批量分享文案解析（2026-09-08，维护者：Codex）

分享管理中的“批量导入分享”先解析预览，再导入勾选记录。支持名称在链接前、后或同一行，Markdown 链接，115.com/s、115cdn.com/s、share.115.com 及缺省协议的分享地址。后端 Service 提取分享编号、名称和访问码，返回统一 https://115.com/s/编号 链接；访问码单独保存，允许在预览修改。保留名称中的容量、部数、年份和版本，去除明确装饰、复制提示和推广文案。

按本次文本的分享编号合并重复；名称和访问码冲突保留候选，名称归属不明或缺失时提示。提示项默认不勾选，用户可修改名称/访问码后勾选。预览显示原文行号及忽略内容。不会核验分享有效性，不与数据库历史记录去重。纯分享链接如未包含名称，需要在预览补充名称。

预览接口 POST /media/share-records/parse 接收 {text}，通过 SuccessResp 返回 records、duplicates、ignored；空文本、无效JSON或没有分享链接返回400。解析不调用网盘、不写库。确认后复用分享创建接口逐条保存；失败停止，已成功项锁定并刷新列表，其余选中项可直接重试。修改原始文本清除旧预览；重新解析只对新文本去重。

### 分享已取消状态（2026-09-08，维护者：Codex）

新增 t_share_record.share_cancelled BOOLEAN NOT NULL DEFAULT FALSE，v24迁移随程序启动在现有事务中执行。识别分享时仅明确的网盘分享取消错误置为true，成功重新解析置为false；任务超时、context取消、密码错误、原因不明的过期/失效不标记。更新状态时核对原链接与密码，避免并发编辑后的旧结果污染。编辑链接/密码自动清除原状态，单纯改名称保留。

列表API返回share_cancelled，名称旁显示红色“分享已取消”标签，刷新后通过数据库字段回显。此次不根据历史任务超时回填取消状态，需重新识别确认。保留原有媒体记录和识别操作。

### 分享剧集海报合并（2026-09-08，维护者：Codex）

列表 Service 对同一分享内已识别成功的电视剧按 TMDB ID（无 TMDB ID 时按元数据源+MetadataID）标记 gallery_duplicate。海报墙默认折叠重复记录，可通过“展开同剧集记录”查看并逐条修正、删除。电影、不同ID、无可信ID或失败记录不按名称合并。该标记由读取时生成，无需迁移或删除历史数据；识别统计仍表示原始记录数量。

扫描判断目录候选仅检查直接子项，避免把集合目录因后代视频误当一部媒体；入库前对已有媒体目录覆盖的 SxxExx 单集候选跳过。裸露在根目录的单集、没有父目录候选的文件和独立电影仍保留，以免丢失混合分享中的内容。

### 清空分享识别内容（2026-09-08，维护者：Codex）

分享管理每行新增“清空识别内容”。确认提示列出分享名称及媒体数量；执行后删除该分享全部 `t_share_media_file` 候选，并清理对应的 `t_share_media` 识别实体，包括已识别、待识别、失败、脱敏和重复单集记录。保留分享主记录、链接、密码及其他配置，不操作115文件。清空完成后可点击“识别”，重新从分享扫描生成候选，不沿用旧单集记录。

DELETE /media/share-records/:id/media 返回 SuccessResp {deleted}。DAO事务锁定分享主行后按share_id删除；空分享返回0，不存在返回404，非法ID返回400。Service在本服务实例有分享识别任务运行时拒绝清空（409），任务锁在创建前获取并在后台终止后释放。该互斥适用于当前单后端实例部署；不提供跨进程任务互斥。


### 已识别媒体分页（2026-09-08，Codex）
分享管理列表仅加载统计；展开海报墙后从数据库按每页10条读取。相同剧集先全局合并再分页，也可展开原始记录；重新识别、手动修正和删除后刷新当前页。


### 海报墙分页偏好（2026-09-08，Codex）
每页条数支持输入1至100的任意整数，点击“应用”后回到第一页。偏好保存在当前浏览器 localStorage 的 share:gallery:page_size 键中；首次默认10条。刷新或重新展开时恢复，不再通过Redis或后端配置接口保存。


### 待识别续跑（2026-09-08，Codex）
分享管理的“继续识别待识别内容”直接处理已入库的待识别候选，不重新扫描网盘、不重试失败记录。跳过已取消分享及脱敏目录，复用任务中心进度、取消和总时限。无待识别候选时正常完成。


### 单分享续跑（2026-09-08，Codex）
每行“继续识别待识别”仅处理该分享已入库的待识别内容，复用批量续跑规则；无待识别内容或分享已取消时禁用。


### 单分享失败重试（2026-09-08，Codex）
每行“识别失败内容”仅重试当前分享数据库中的failed记录，不重新扫描目录，不处理待识别或已识别内容。无失败记录或分享取消时禁用。


## 分享资源库与统一定时任务（2026-09-09，维护者：Codex）

分享识别成功时，文件候选才关联新建或已有的 `t_share_media` 实体，并通过实体表的查询投影字段进入作品级资源库；未匹配内容只保留在 `t_share_media_file` 供错误展示和重试。资源库支持 TMDB ID、媒体分类、年份、题材、评分、国家或地区、有效分享和排序筛选，按作品聚合并保留全部分享来源；历史缺失元数据通过任务中心启动可取消的补全任务。

电视剧资源详情按“季 → 集 → 分享文件”展示。季概览来自 TMDB，展开某季时按需读取完整分集目录，并将 `t_share_media_file_episode` 中的本地映射挂到对应集；没有文件的集仍展示，同集多来源和一文件多集均保留。TMDB 暂时不可用或作品没有可用 TMDB 身份时，接口降级返回本地已关联季集并显示警告，不隐藏已有资源。电影继续使用原有来源分页列表。

系统定时任务统一由处理器注册表和 `t_cron_task` 管理，配置包含 Cron 表达式、时区、JSON 参数、启停状态和执行记录。STRM、账号冷却恢复、日志清理和识别缓存清理使用同一调度入口；同一任务或 STRM 配置正在运行时，重复触发会记录为跳过。


### 分享标题与ID识别（2026-09-09，Codex）
保留标题内部数字和中英文混排。已知媒体类型且文件名含[tmdbid=数字]时优先读取TMDB详情；普通查询失败后核对TMDB官方别名，仍要求年份及唯一身份匹配。原始文件路径不修改。


### AI兜底规则（2026-09-09，Codex）
分享识别先执行标题规则、TMDB搜索与官方别名核验，成功则不调用AI。复杂标题及类型不确定场景也在常规识别失败后才触发；仍遵循AI开关与场景配置，一次识别最多调用一次AI，建议必须通过TMDB核验。


### 目录年份回退（2026-09-09，Codex）
剧集查询因目录年份未能确认时，先去掉目录年份重查，再考虑AI；仅接受完整标题对应唯一TMDB身份，同名歧义仍需核对。
