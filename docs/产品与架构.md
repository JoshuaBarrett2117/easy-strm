# 产品与架构

## 任务通知范围（2026-10-19，维护者：Codex）

系统设置 → 通知提供独立的任务通知范围，列出全部调度任务（含停用任务），支持全选、全不选、反选和单独保存。它只限制任务事件，不影响 115 账号状态通知；各渠道原有事件开关、发送协议和去重保持不变。

认证接口 `GET /api/notify/task-scope` 在 `SuccessResp.data` 中返回 `{selected:[],tasks:[{task_key,task_name,handler,status}]}`；`PUT /api/notify/task-scope` 接受 `{selected:["task:xxx"]}`，成功返回 `SuccessResp.data.selected`（去重）。请求上限 1 MiB，缺失/null/非字符串元素、当前调度表中不存在的键返回 400，配置或任务表故障返回 500。`[]` 是有效的显式全不选，可再次 PUT 修复损坏配置。

`t_system_config.notify_task_keys` 保存稳定键 JSON 数组，优先使用 `CronTask.TaskKey`，仅无键任务使用 `handler:<handler>`；不保存自增 ID。通过支持请求取消和两秒写入预算的 `BatchUpsertContext` 事务同时写入 `notify_task_scope_configured=true`，原 `BatchUpsert` 签名保留并复用同一事务实现。两键属于保留配置，通用 Settings/SystemConfigService 单键写入拒绝、批量写入排除，不能绕过专用接口的校验及原子写入。未配置、空白及无标记的历史 `[]` 兼容为全部任务；历史非空数组直接限制范围；显式保存后严格选择，空数组静默全部任务。损坏配置或读取故障时任务通知关闭，但账号通知继续运行并保持续期基线，无需迁移。

调度器在普通和并发跳过执行的 Redis 元数据中写入 `cron_task_key`。监控器批量读取当前调度表，为旧执行的 `cron_task_id` 映射稳定键，不使用执行 `task_id` 或 `task_type` 推断身份，也不为有键任务按处理器回落。共享处理器的有键任务保持独立；仅处理器无法区分有键和无键任务时保守静默。限制范围内未识别的手动任务静默；尚未绑定元数据的 pending 执行延后判定（包括初始化竞态），不抢占其事件。已观察到的未选中事件记录静默去重，后续勾选不补发；正常初始化仍不补发历史事件。

稳定性以复用同一个 `TaskKey` 为前提：调度页面新建任务时生成 `task:<UnixNano>`，删除后重新新建会获得新键，需要重新勾选；给无键旧任务补上真实键后同样需要重新选择。多个无键任务若处理器相同，按回落键成组勾选，界面仍逐行列出并按实际任务数显示已选数量；需要独立控制时应为其建立独立 `TaskKey`。通知任务快照兼容旧表空状态（`COALESCE(status,'')`），前端显示未知状态。

来源：`easy-strm/internal/service/notification_task_scope.go`、`easy-strm/internal/service/notification_event_monitor.go`、`easy-strm-front/src/components/settings/NotificationTaskScope.vue`。

## 分享批量删除（2026-10-12，维护者：Codex）

分享管理在“批量清空识别内容”旁提供“批量删除分享”。确认时固定所选ID并显示数量，沿用单条删除的不可恢复风险提示：删除同步文件记录、STRM数据库记录及生成的STRM文件，网盘原文件不受影响。选中目标已有清理、同步或识别任务时禁用操作；其他分享不受影响，确认回调再次检查目标状态。

认证接口 `POST /media/share-records/batch-delete` 接受 `share_ids` 整数数组，空、格式错误、非正数或null项返回400；提交校验时不存在返回404，队列/读取异常返回500，成功返回 `ShareOperationAccepted.task_id`。服务复用现有 `share_delete` 队列、排序去重、逐ID校验、资源协调和原单条删除逻辑，不增加批量上限或改变服务端入队规则。等待阶段可取消，执行阶段不可取消。

多目标任务逐项执行完整删除流程，失败继续后续目标，运行时不存在的分享计为跳过。成功ID与该分享删除在同一事务内写入检查点，单项事务不提前完成整个任务；重启后仅跳过已提交成功项，其余目标重新尝试。全部尝试结束后一次性写入终态和 `deleted`、`deleted_ids`、`failed_ids`、`skipped_ids`，任一错误使任务失败并保留ID及原因。部分失败也使成功目标的旧任务快照失效；终态失败不会自动重试，用户可保留失败选择重新提交。

页面通过现有任务轮询展示实际成功数量和部分失败警告，只移除成功/跳过的选择，保留失败目标并刷新列表。旧版单条结果缺少ID数组时按单条目标回退，单条删除完成事务保持原样。

来源：`easy-strm/internal/service/share_operation_queue.go`、`easy-strm/internal/dao/share_operation.go`、`easy-strm-front/src/views/ShareRecords.vue`。

## 人工基线采纳执行预算（2026-10-11，维护者：Codex）

人工采纳总时限由5分钟改为缺省20分钟，使用既有系统配置存储的 `share_strm_baseline_adoption_timeout_minutes`。请求可通过可选 `timeout_minutes` 覆盖，省略/null 使用配置，显式0表示无限制，允许0至43200分钟。任务提交时读取配置并固定预算；现有任务取消机制及原子不可取消提交守卫不变，增加时限不放宽采纳资格。

DAO 将计数、映射核验和来源播种改为集合化查询。存在性检查只对成员集合去重；映射按全部原始校验输入分组并保留精确 multiplicity，Go 仍使用真实 `BuildShareStrmEntry` 和严格 JSON 解码，原映射身份、媒体、URL、文件语义不变。严格/良性查询仅相差实际媒体 ID 相等条件；remaining为0、精确放行数量、200硬上限、人工核验、所有锁、输出路径和快照护栏、回滚、同事务 finish 与审计保持不变。生产60秒目标必须由 DBA 真实查询计划/完整流程证据确认，不能从隔离合成数据推断。

自有输出与映射一次物化，使用受 CASE 保护的规范小写 UUID 探测原生主键索引，并继续要求原始 UUID 文本相等；这不是 ID 归一化，也不接受原连接拒绝的大写、紧凑、花括号或空白格式。既有 DSN 并行修复及数据库设置不变。

来源：`easy-strm/internal/domain/share_baseline_adoption.go`、`easy-strm/internal/dao/share_baseline_adoption.go`、`easy-strm/internal/service/share_baseline_adoption.go`。既有作品重导使用相同全局计数语义，不修改它的业务资格或输出规则。

## 显式有界作品 STRM 重导（2026-10-11，维护者：Codex）

普通导出的 `domain.BuildShareStrmEntry` 仍只按分享码和源文件路径生成 ID，不改变普通增量/全量。只有显式作品重导使用 `BuildShareWorkReexportEntry` 加 item_key 盐；**每 item 独立 mapping，同媒体多集也不共享**。预检同时覆盖目标新/历史预期 ID、目标 item 当前 active state 的旧 ID、文件旧 URL ID、同输出路径非 missing state 与同稳定路径 selection。全部引用去重；缺 selection、空白 work_key、范围外作品、未列入实际处理目标的 active export_key 或超过20,000引用均拒绝，并给出最多100条有界清单与总数/截断。闭包完整时允许跨媒体共享的 C1/C3，C2/C4/C5/C6 路径和 owner 硬冲突保持原语义。

异步任务的失败、取消、完成及 panic 终态持久化在结束时创建独立十秒超时上下文，不因任务取消而跳过，也不无限等待任务存储；不在任务启动时提前消耗终态预算。

认证入口复用 `POST /media/share-library/strm/export?mode=work_reexport`，仅接受明确的 JSON 作品清单，不提供新页面或调度入口。必须填写 `work_keys`、审计理由 `reason`、`expected_output_path` 与 `expected_config_revision`；操作者由认证中间件注入。清单必须含 1–100 个唯一非空作品键，禁止通配符、控制字符、首尾空白和混合筛选；整个任务最多 10,000 条选择行，预算 30 分钟。空列表、未知作品、空稳定路径、协议缺失或读取失败均拒绝，绝不回退普通全量。

服务只读点查每个作品已有选择，按 `selected_candidate_id -> source_file_id -> f.media_id` 取得实际媒体；不按相同 work_key 猜测媒体行，也不对候选做自动重选。专用 metadata-only 路径不调用普通 writer：STRM 必须存在且真实原字节/路径 hash 匹配旧 state；原 URL mapping 与旧 state mapping 必须和候选指向同实际分享文件，其他文件即使伪造 content hash 也拒绝。不修改任何文件字节、路径或 mtime。新 mapping payload 经域构建器生成，映射指纹取真实新 payload；content 指纹保留真实旧文件凭证。同事务确认 exported_revision，不修改候选、选择模式/版本或稳定路径。

该入口允许 `required`、`building` 和 `ready`，不要求已有基线可信；持有既有目录共享锁与 share owner 锁，复用来源/身份/路径占用和 selection 锁。整批在 output.Conn 的一个事务内重查闭包，锁定配置版本/来源行，执行新 mapping 插入、state 重绑与 selection CAS，并复核写后映射/state/文件及历史 mapping 无遗漏 active 引用。历史 mapping 不覆盖、不删除，无 active 引用后自然作为播放历史行保留；已存在新 ID 的 payload 不同也拒绝，不强行改写。禁止通用 resume，显式重试仍完整核验；普通导出规则不变。

任务返回 `task_id`，审计保留在 `metadata.work_reexport_request`、`metadata.confirmed_by` 与 `metadata.work_reexport`。结果含请求/完成作品清单与数量、选择行数、已处理行数、逐作品状态/错误，以及 `global_invalid_before`、`global_invalid_after`、`invalid_scope="global"`。前后计数原样复用 `shareBaselineCountsSQL`，是**全库只读计数，不是请求范围计数**；读取失败为 null 并使任务失败，不伪装成零。任务完成只表示请求范围重导成功，即使全局 invalid 非零也不会扩大范围，更不代表基线可采纳。

该操作不调用选择发现/候补、全量来源扫描、检查点播种、dirty ack、基线信任推进、全量收尾或采纳，不接触 Emby、115 或 TMDB 网络。已有采纳 SQL 与全部护栏保持不变。提交前失败或取消整批回滚，无部分作品提交；提交后的任务审计/全局计数失败不撤销已成功提交的元数据，可重新显式幂等重试。文件从不改写，因此不存在已发布文件回滚。应用锁无法阻止绕过协议的数据库写者或外部进程改文件，真实 PostgreSQL 查询计划/并发性能与最终 diff 仍需父审/DBA 独立核验。

兼容性限制：按要求不改采纳护栏，现有 `share_baseline_adoption.go` 的映射核验仍要求 `BuildShareStrmEntry` 的 legacy ID，因而会拒绝重导生成的独立 item ID；即使全局 invalid 计数为0也不等于能采纳。普通导出仍使用 legacy ID，后续普通导出可能再次按原规则重绑，不能把人工拆分当作全模式的永久新契约。这些后续行为必须单独审核，本入口不绕过或改写它们。

来源：`easy-strm/internal/service/share_work_reexport.go`、`easy-strm/internal/dao/share_work_reexport.go`、`easy-strm/internal/dao/share_work_reexport_metadata.go`；调用示例与本地证据见 `docs/开发与测试.md` 和 `/opt/data/output/estrm_shared_mapping_codex_notes.txt`。sqlmock 不能替代真实 PostgreSQL 查询计划或并发验收。

## 人工采纳已独立核验的分享基线（2026-10-11，维护者：Codex）

受控良性放行（2026-10-11，维护者：Codex）：可显式提供 `allow_known_benign_invalid` 与 `benign_attestation`，缺省为 0、不开启放行。数量必须为正、精确等于原始 invalid 与同一选中文件仅 MediaID 不同的映射行数，且不超过命名硬上限 200；说明去除首尾空白后必须非空，但事务审计保存原文及请求数量、认证 actor、时间。额外计数仅省略 payload MediaID 与 live ID 相等的 SQL 谓词，其他谓词全部保留，剩余 invalid 必须为零；其余映射身份检查不变。仅成功提交后记录 WARN 数量，ready no-op 不变。该能力不修改已有映射、文件、schema、作品重导或 preflight。来源：`easy-strm/internal/dao/share_baseline_adoption.go`、`easy-strm/internal/domain/share_baseline_adoption.go`。

提供仅显式调用的认证 API `POST /media/share-library/strm/baseline/adopt`，用于承认 DBA 已独立核验的 building 基线，而不是代替核验或自动降级全量。提交者必须给出确认短语、理由、DBA 核验引用、输出路径与完整计数/版本护栏。API 返回任务 ID；任务中心详情给出人工采纳标识、ack 数、来源检查点数、selection/output 数、新基线状态与 completed_revision。

Controller 仅严格解析参数并注入 JWT 用户；Service 校验确认、快照配置与指纹并管理可取消任务；DAO 使用既有目录树、owner、selection 锁协议，结合 NOWAIT 表锁原子阻断生产者/配置/输出写入，验证选择与现有输出凭证，补来源观察/输出关联、集合消费 baseline backlog，并复用 ready/成功水位收尾。审计凭证与业务记账同事务持久化到既有配置表，无迁移，无文件读写、NAS、TMDB/115 或真实账号调用。

ready 后重复采纳为业务 no-op，绝不 ack 新增增量待办。配置改变、required、协议/护栏/一致性失败均拒绝；普通全量与增量执行语义保持不变，增量仍需可信且完成的基线。该能力没有自动调度、通用任务恢复或普通导出按钮的隐式入口；前端仅提供 API wrapper。运维先重新独立核验再显式提交，不应从历史数字拼造护栏。锁定期会短暂阻塞相关写入；集合查询耗时与真实 PostgreSQL 并发语义需父审/DBA 独立验收。

来源：`/opt/data/output/dev_estrm_baseline_adopt_prompt.txt`、`docs/开发与测试.md`；准确调用示例与安全边界见 `/opt/data/output/dev_estrm_baseline_adopt_notes.txt`。

## P0 全量完成与消费终态（2026-10-11，维护者：Codex）

全量成功落盘之后仍需消费已播种的作品待办，建立成功来源快照、计划键及 dirty revision 确认，最后由 `FinishBaseline` 原子检查配置和全队列后进入 ready；不能仅因落盘完成便跳过消费。空队列直接收尾，不刷新来源选择；有待办的增量/恢复运行只在消费目标作品前准备该作品，schema 每次运行检查一次，绝不全局同步或解析无关失效手选；当次全量已准备则复用结果，额外同步为零。准备后只刷新同作品 dirty revision，源观察/版本/季集及既有选择凭证校验不通过时保留 pending；游标前新入队作品不被顺带确认。每次最多 1,000 个游标页，未完成返回可重试错误，不把竞争、失败或取消标记成完成。

任务 metadata 成功后 `phase=completed`；异常终态区分 failed/cancelled/pending。每十作品及页末报告尝试/累计确认作品数、本轮确认数 `round_consumed_works`、失败数、游标、轮数及待办。待办使用既有 100 项 keyset 探测，满页为下界并令 `pending_works_exact=false`，不引入完整统计查询。`completion_boundary=finish_baseline_cas` 指事务完成边界快照；之后并发重新入队可令收尾探测显示非零 pending，保留待下次消费。收尾进度/metadata 失败返回错误，不声称完成状态已可靠持久化。全量任务保留原有来源进度和落盘/去重指标，后续消费计数独立记录；来源与季集统计单位的既有差异不在本次修复范围。

来源：`internal/service/share_strm_incremental.go`、`internal/service/share_strm_scheduled.go`、`internal/dao/share_export_checkpoint.go` 与 `/opt/data/output/estrm_p0_codex_task.txt`。验证范围及 RED/GREEN 证据见 `docs/开发与测试.md` 的 P0 节；没有 schema/迁移/DAO SQL 变更，没有生产或 NAS 操作。

## 在线读取快照与性能边界（2026-10-11，维护者：Codex，待父审与 DBA 复审）

- 来源候选同步仍保持发现事务的原子性、身份归属与 FK 顺序。临时 observed 增加非唯一身份查找索引，不新增身份拒绝约束；候选所有可变字段使用空值安全差异判断，仅变更数据或恢复 revoked 项时更新时间。首句 advisory 后限制后续锁等待 30 秒，HTTP 刷新连同 schema 检查共用 15 分钟预算，不转成不可追踪的后台请求。
- 分享同步仅按主键读取名称、链接、目录及版本配置，不为一次同步入口生成该分享全部媒体 JSON。完整 SyncFiles 扫描、身份/版本 CAS 与可用性收尾协议保持原样，本轮不擅自拆事务或提前标记未扫描文件失效。
- 作品库先过滤作品字段，再决定聚合范围；年、标题、评分排序允许先取本页后统计来源，收集时间排序仍在过滤集合上计算 `max(file.created_at)` 后取页。真实文件页与来源页仅批量构建本页季集 JSON，保留原有精确总数、筛选、空值排序与随机页契约；未引入可能在 UPDATE 后漏项/重复的时间游标。
- Emby 概览先尝试插件，成功不读本地历史聚合；失败才完整计算本地汇总。概览五秒缓存、并发 singleflight、15 秒请求预算，每次仍按主键验证实例启用与地址/密钥配置。返回独立副本，不将缓存改动传播给其他请求。

只标 stale，不删除磁盘或归属历史；新增 cron/API、低频调度、stale 删除/灰度属 phase03，本轮没有接线。v43 绝不进入启动链，两条大表路径索引由 DBA 事务外 CONCURRENTLY 预建，真库语法/迁移/性能门禁仍待执行。设计与执行证据参考 `/opt/data/output/easy-strm-phase02/resume-codex-review.md`、`dba-execution-handoff.md` 和仓库 `debug/phase02/README.md`。

## 分享资源协调与持久化清理（2026-10-07，维护者：Codex）

取消分享同步、识别和导出的全局业务互斥。分享 ID 使用生命周期共享占用，删除和清空独占对应分享；同步只串行扫描同一分享，识别按文件候选串行；导出按作品季集身份保护命名重算，按分享码与文件路径保护播放映射，按规范化文件路径保护 STRM 写入、删除和清单登记。普通输出共享目录，整目录清空独占目录，清空结束即降回共享。资源状态互斥锁只用于登记和唤醒，数据库、网络与磁盘工作在锁外进行。

删除分享、删除文件候选、单分享清空、选中及全部清空统一先持久化到 v42 的 `t_share_operation_queue` 再返回 `SuccessResp({task_id})`；MCP `share_record_delete` 同样返回任务 ID。重复提交同一未结束操作复用原任务。任务中心展示等待原因、冲突任务 ID、执行阶段、完成数量及具体错误。确认框说明可能等待，接受后提示“已提交”；只有任务完成才提示删除或清空完成。仅目标行及目标文件的重复操作受限，其他行、文件和浏览继续可用。

入队后目标清理优先于后续业务单元，多个目标原子取得资源，不占用未实际处理的整个业务批次。清空成功使旧批次目标失效，单文件删除使此前提交的同步跳过该文件；后续用户显式同步可重新创建候选。等待后重新读取来源并保留文件版本校验，过期结果不能覆盖新版本。全量导出仅更新本次快照中未见且清单版本未被其他任务改变的项。

PostgreSQL 是清理队列事实来源，Redis 用于任务展示。启动先恢复所有等待标记，再开放入口；使用原任务 ID 按阶段继续，已经删除的目标视为完成。数据删除与完成日志同事务提交，磁盘已删除而事务未完成可依靠持久清单幂等续跑；完成但任务展示未同步时只补发结果。取消或失败操作不自动执行重试；磁盘清理失败保留分享记录，用户可重新提交。状态同步短暂失败会自动补发，前端轮询自动重试。清理等待不自动超时，用户可取消；同步与识别保留现有时限，多个任务共用并发预算。


## STRM 多任务执行（2026-09-28，维护者：Codex）

多个 STRM 配置可在同一时间触发全量生成。普通输出共享目录树并只独占实际文件路径；不同路径可以并行，整目录清空独占目录并等待其子路径任务释放共享占用，避免并发清空、覆盖或文件归属登记冲突，不再因瞬时目录占用直接失败。等待期间可在任务中心取消；配置与目录资源累计等待超过 30 分钟后超时结束。配置页直接生成和恢复任务也采用可取消的配置等待。同一定时任务或同一配置的重复调度触发仍跳过，防止重复积压。

## 分享作品识别与季集复用（2026-09-23，维护者：Codex）

分享识别复用通用文件名规则，明确的罗马部数按季号解释：`妙手仁心Ⅰ-31.mkv` 对应 S01E31，`妙手仁心Ⅱ-01.mkv` 对应 S02E01；查询名均为“妙手仁心”，跨季共享同一个 TMDB 剧集身份。支持 Unicode 罗马数字及 I–XII 的 ASCII 写法。普通 `标题-01` 需要明确电视剧类型、剧集目录上下文，或同目录同标题同时存在 01、02 连续编号，才推断为单集；原始文件名和网盘路径不修改。

任务按分享、目录上下文、规范化标题、年份、类型及元数据策略复用作品身份，纯 Season/Sxx 季目录不拆分作品。同组并发请求合并，季集号始终逐文件保留；已落库身份只有通过当前标题、年份和类型核验才用于新集，历史身份相互冲突时保留待确认。Redis 作品缓存使用独立 v1 命名空间与规则配置指纹，有效期七天；缓存中心 TMDB 缓存组包含这些键。普通任务复用已识别文件和作品，显式重新识别绕过作品缓存及 TMDB 搜索缓存，手动修正使相关作品缓存失效。

常规识别无匹配后才允许 AI 辅助，同一任务每作品最多调用一次，AI 建议仍需通过数据源核验，不能覆盖已明确的 tv/movie 类型或文件季集。网络和别名接口故障不作为内容无匹配触发 AI，也不持久缓存为失败身份。失败结果不补详情；成功结果按作品补元数据，并使用剧集详情中的季目录核对季号。对应季缺失或详情不可用时保留作品 ID 与解析季号，在分享文件“识别说明”中显示“季信息待核对”，不改查电影。

## 分享同步与识别并行（2026-09-22，维护者：Codex）

分享文件同步与媒体识别可同时运行，页面分别跟踪所有活动分享任务。识别只处理任务加载时已入库的候选，新同步文件可通过“继续识别待识别内容”处理。

同一组分享的重复同步请求（含乱序或重复 ID）在任务运行期间返回相同任务 ID；不同组的同步可以并行，同一分享的扫描与落库串行，多个任务共用同步并发预算。任务结束后允许重新扫描。同步以分享及远端文件 ID 匹配已有记录，无远端 ID 时按路径匹配，不重复建档，不清除未变化文件的识别结果和季集关联，也不递增其识别版本。SHA1 确认变化时重置识别，路径变化时递增版本以阻止旧路径识别结果覆盖。扫描时间仍正常刷新。清空仅等待选中分享的活动单元结束后执行，其他分享和文件浏览可继续。

## 分享文件与媒体主数据（2026-09-12，维护者：Codex）

分享处理拆为两个独立任务。`POST /media/share-records/:id/sync` 递归解析完整分享目录，只把真实视频文件同步到 `t_share_media_file`；每次完整扫描使用唯一标记 upsert 文件并在成功结束后标记未出现的旧文件为失效，解析失败、超时或脱敏目录不会误删或伪造文件记录。文件优先按分享 ID 与 115 文件 ID 去重，没有远端 ID 时才按完整相对路径去重。

`POST /media/share-records/:id/identify` 只读取已落库且有效的文件，不再隐式扫描分享。匹配成功后按“元数据来源、提供方、媒体类型、外部 ID”全局 upsert `t_share_media`，不同分享、季和集共用同一媒体主记录；未匹配文件只更新文件状态和错误，不创建媒体主数据。电视剧必须具备季集信息，`S01E01E02` 等多集文件在 `t_share_media_file_episode` 保存多行映射，手动识别也必须同时提交有效季集。

资源库直接读取全局媒体主表，并通过有效文件统计分享来源数和文件数。文件级接口 `GET /media/share-records/:id/files` 返回路径、有效状态、错误、媒体关联和季集映射；媒体海报接口按 `media_id` 聚合。STRM 只使用有效且已识别文件，电视剧以持久化季集映射为准，多集文件为每集生成一个入口并共同指向同一真实文件。数据库由 `migrate_v33_share_media_master.sql` 从已执行的 v32 迁移，脚本包含历史目录清理、全局身份去重、本地多集回填、唯一索引及上线校验。

## 分享资料库 STRM 导出与播放（2026-09-13，Codex）

分享资源库右上角「导出 STRM」可配置服务器导出目录、播放访问地址、已配置的 115 账号和网盘转存目录。导出范围为当前已应用筛选条件下的全部作品，不受页面页码限制；未标记取消且已识别的来源参与导出。导出在任务中心执行，可查看生成数量、失败详情和取消任务。

目录复用整理规则的分类匹配与分类路径拼接行为（取命中分类目标目录的最后一级），无匹配时使用 `movie` / `tv`。例如 `国产剧/作品 (2024) {tmdb-10}/Season 02/作品 - S02E03.strm`。电影为 `分类/片名 (年份) {tmdb-ID}/片名 (年份) {tmdb-ID}.strm`。季集使用当前文件名识别规则，支持特别篇第 0 季，以及 `Season 02/EP03.mkv`、`第2季/03.mkv`；单文件手动识别中明确保存的季集优先。不能确定集数的文件记录失败，其他可识别文件仍导出。重复导出更新同名文件，不清理历史目录。

同作品同集存在多个分享时，文件名追加分享名称；同名分享再追加分享 ID。同一分享内存在多个有效文件来源时，每条文件追加稳定的本地文件来源 ID，例如 `片名 (年份) {tmdb-ID}-文件123.strm`；同时涉及多个分享时则为 `片名 (年份) {tmdb-ID}-分享名称-文件123.strm`。该来源 ID 同时参与导出归属键，保证重复导出仍更新各自文件。更新日期：2026-09-30；维护者：Codex。

STRM 内容为 `{播放访问地址}/share-strm/{稳定ID}`。扫描候选、待识别和失败状态保存在 `t_share_media_file`，只有识别成功的媒体信息才进入 `t_share_media`；两表通过可空的 `media_id` 关联。导出仅分页读取这两张本地表中的文件路径和已匹配结果（关联本地分享主表读取地址/提取码），不重新访问分享链接、不请求 TMDB、不转存视频。仅有目录、没有具体视频文件的记录会报告失败，不进行网络补扫。GET / HEAD 播放请求读取 PostgreSQL 播放映射，在配置的 115 目录下按 ID 建立独立子目录。首次播放缺少文件 ID 时，沿本地保存的相对路径逐级读取所在分享目录，定位具体视频并缓存 ID，不遍历无关目录；后续转存复用 ID。只转存对应的视频文件；数据库事务锁串行化同文件转存。已有同名视频直接复用，服务重启后仍可使用。直链按当前播放器的 User-Agent 获取，每次返回 302，不缓存临时签名链接；分享转存、账号、列表或直链失败返回明确错误。播放转存不会清理网盘文件。

分享 STRM 成功返回 302 后与普通 STRM 共用播放记录表，GET 与 HEAD 预解析均进入记录链路，失败请求不记录。播放器对同一资源的 HEAD/GET、重试及临时直链刷新按“资源稳定标识 + 来源 IP”归入同一播放会话；连续解析会延长会话，静默超过 5 分钟后再次访问才新增记录。导出映射同时快照媒体主数据 ID、标题和海报路径，记录时优先使用快照；旧映射则按分享码及文件 ID/路径回查 `t_share_media`，从而不依赖普通整理链路的文件名识别缓存。新播放记录会带入当前可用海报；分享历史记录因旧数据没有稳定分享映射 ID，不做可能串图的自动改写。

普通 STRM 的标题和海报来自 `t_identify_cache`。识别结果落库必须同时保存 `poster_path`；对于旧版本漏存的 TMDB 海报，启动迁移按媒体类型与 TMDB ID 从本地 `t_tmdb_cache` 回填，再按精确文件名哈希或唯一标题补齐历史播放记录。整个修复过程只使用本地数据，不在播放请求中发起 TMDB 网络访问；未识别文件或本地从未缓存过海报的媒体仍显示无海报。

配置复用系统配置表的 `share_strm_settings`，播放映射使用 `t_share_strm`，启动时执行内嵌的 `migrate_v29_share_strm.sql`。映射拥有稳定分享码与路径身份；删除分享会清理其播放映射及对应 STRM，但其他分享记录仍引用同一分享码时保留共用映射和文件；播放仍依赖分享可转存或目标账号已存在对应视频。修改目标账号或网盘目录后，已有链接读取新设置；修改播放访问地址或导出目录后需重新导出。

部署时将导出目录挂载给 Emby / Jellyfin 等媒体服务器，并确保其能访问配置的播放地址。Docker 内路径须使用容器中的绝对路径；内置 Nginx 和 Vite 已代理 `/share-strm/`，使用自建反向代理时也需转发此路径到后端并保留 User-Agent、302 响应，预留首次转存耗时。此能力需要有效的 115 账号及分享；本地模拟测试不代表真实账号转存可用性。

## 1. 产品定位

`easy-strm` 是面向个人媒体库的文件整理与 `.strm` 生成工作台。产品聚焦高频、可直接操作的媒体处理流程，不承担下载器管理或完整媒体资产治理平台的职责；资源获取仅覆盖 115 分享转存与 115 云下载（离线下载），不接入资源搜索与 PT。

核心流程：

```text
媒体源接入
  -> 文件浏览与选择
  -> TMDB 自动或手动识别
  -> 重命名与整理预览
  -> 移动、复制或链接
  -> 可选元数据刮削
  -> STRM 生成
  -> Emby 刷新与任务追踪
```

## 2. 功能范围

### 2.1 媒体源与文件

- 本地目录与 115 云盘媒体源。
- 媒体源启停、排序、监控目录、整理目标、媒体类型和冲突策略。
- 文件分页浏览、搜索、筛选、面包屑导航与批量选择。
- 本地和 115 文件移动、复制、删除、重命名；本地支持硬链接和软链接。

- Docker Compose 部署 PostgreSQL、Redis 和应用服务。

### 2.5 资源聚合与 115 云下载

- **115 分享转存**：分享链接一键解析与批量转存。
- **115 云下载**（离线下载）：
  - 支持一次提交多条 ed2k、magnet、http/https、ftp 链接，自动去重、去空白并过滤不支持的协议。
  - 可选择 115 账号与保存目录，未指定目录时默认使用 `/云下载`。

  - 批量提交被 115 以「任务已存在/链接无效」整体拒绝时，自动降级为逐链接提交，精确标注每条链接的受理结果。
  - 链接已存在离线任务时不重复提交，而是关联现有任务并继续跟踪其状态。
  - 提交成功返回任务中心任务 ID，云下载任务可在任务中心查看进度与结果。
  - 后台跟踪协程轮询 115 离线任务状态，把记录推进到完成、失败或已移除等终态；115 侧配额不足、登录失效等错误归一化为可读提示。
  - 云下载记录支持按账号、状态分页查询，删除记录时可选择是否同时删除 115 侧任务与已下载文件。

## 9. Telegram 115 资源操作

- 更新日期：2026-08-30
- 维护者：Codex

管理员私聊可直接发送115分享链接或云下载链接。消息语法统一为 `链接 [账号名称] [/目标目录]`：账号和目录都可省略，也可单独指定；目录必须是以 `/` 开头的115绝对路径。

Telegram 与企业微信应用回调均支持在一条消息中按行提交多个资源操作。每个非空行独立使用上述语法、独立选择账号与目录并创建一个任务；某行失败不会阻断后续行。处理完成后统一返回总数、已创建数、失败数，以及每行任务 ID 或错误原因。

- 分享转存默认选择活跃资源号，按账号优先级降序、账号 ID 升序；未指定目录时使用该账号配置的默认转存目录。
- 云下载默认按 VIP 观影号、兼顾账号、资源号的类型顺序选择；同类型按账号优先级降序、账号 ID 升序；未指定目录时使用 `/云下载`。
- 指定账号名称时不应用默认账号类型限制，但账号必须处于活跃状态且具有可用登录态。
- 机器人只负责编排现有 `ShareTransferService` 与 `OfflineDownloadService`，提交后返回任务卡片；真正完成时由统一任务终态监控发送成功通知。

## 10. 媒体源监控与自动整理

- 更新日期：2026-08-30
- 维护者：Codex

媒体源的“启用”是监控和自动整理的总开关；只有媒体源已启用且目录监控已开启时，后台才会运行监听。文件工作台会结合 WatchService 的当前运行状态，明确区分“媒体源已停用”“未开启监控”“监控未运行”“仅监控”和“自动整理中”，不再仅凭保存的监控开关显示运行中。

本地媒体源通过 fsnotify 监听整个目录树，新进入的文件夹也会被纳入监听；115 媒体源按配置间隔递归、分页扫描监控目录，并仅将相对初始快照新增的视频文件送入自动整理。初始目录读取失败时监控不会启动，避免把历史文件误判为新增。
### 自动混合类型与 AI 辅助识别（2026-09-08，维护者：Codex）

分享管理“识别任务设置”配置扫描与识别合计的总时限，支持无限制（0，默认）或1–43200分钟。配置保存在系统配置表share_identify_timeout_minutes，新任务启动时读取，运行中任务不追随更改。无限制仍可通过任务中心取消，各外部接口保留自身请求超时。达到自定义时限明确提示分钟数，不再与分享取消混淆。接口GET/PUT /media/share-task-settings使用timeout_minutes字段。

批量识别遇到网盘明确取消的分享时，保存取消标签并跳过该分享及其历史媒体，继续下一条；任务展示已跳过取消分享数量。全部分享取消时正常完成，不按无媒体报错。任务超时和密码错误不作为分享取消处理。

新分享默认按单条媒体自动判断类型，编辑支持自动（混合）、电影、电视剧。历史显式类型不会批量覆盖。分享识别从原始路径派生中文名、英文名及年份，不修改文件名或网盘数据；排除集合目录查询，避免将剧集全集光盘按电影检索。候选须满足规范化标题或原名一致、年份相差不超过一年；同名同年的不同身份不自动选定。

分享识别绕过旧文件匹配缓存，保留TMDB搜索和详情缓存。单条分享“识别”和媒体“重新识别”会重新核验已有内容。扫描候选按分享与完整路径事务幂等写入，任务按路径去重，已被剧集目录覆盖的单集和剧集分碟不新增。历史重复记录不自动删除，可清空后重建。任务优先待识别、其次失败、最后已识别；总时限由识别任务设置控制，默认无限制；中断后可重新发起继续处理待识别项。同一实例允许多个分享识别任务运行，共用识别并发预算；同文件识别、核对、删除及导出串行，不同文件独立执行。

AI配置页位于 `/dashboard/ai-recognition`，统一服务接入分享识别、整理预览、自动监控整理、历史识别失败重试、手动识别预填、识别测试和无缓存刮削补全。支持OpenAI兼容接口根地址（例如含/v1）、API Key、模型、超时、提示词及场景开关。使用GET /models获取模型，POST /chat/completions发送messages、model和stream=false；不强制response_format以适配兼容端点。保存过连接信息后进入页面自动获取模型，也支持手动获取或填写模型ID；模型是否支持聊天需用测试按钮确认。

AI默认关闭；首次配置默认勾选复杂标题和常规无可靠匹配，类型不确定需显式开启。每条媒体每轮最多一次AI调用；输出仅作为片名、原名、年份和类型建议，仍经媒体数据库核验。手动弹窗的 AI 解析只预填表单，必须选择数据源候选后才能应用。刮削详情、ID、图片和 NFO 内容只来自 TMDB、MetaTube 或已有缓存。播放请求永不调用 AI。AI故障不影响普通识别；无可靠匹配不标成功。启用后原始路径会发送至配置端点。

配置以ai_recognition JSON复用系统配置表，专用接口原子保存和热更新：GET/PUT /settings/ai-recognition、POST /settings/ai-recognition/models、POST /settings/ai-recognition/test。公开响应不返回已存密钥；地址未变时空密钥保留，更换地址不自动携带原密钥。原始路径及已存分享内容不因此改变。

协议参考地址：https://platform.openai.com/docs/api-reference/chat/create 、https://platform.openai.com/docs/api-reference/models/list 。本次官方页面返回403，兼容行为通过本地模拟端点验证，未核验真实AI供应商。

# 全局第三方 API（2026-08-30，Codex）

系统提供全局 API Key 配置，第三方通过 `X-API-Key`（或 `Authorization: ApiKey`）直接调用现有业务路由，无需复制路由树。API Key 仅由专用接口管理，通用设置接口不会返回或修改密钥。企业微信回调仍使用自身签名校验，回调 URL 根据全局外部 API 地址生成。

同时提供 `POST /mcp` MCP JSON-RPC 入口。AI Agent 使用同一全局 API Key 完成 `initialize`、`tools/list` 和 `tools/call`，协议版本保持 `2024-11-05`。原有核心工具继续通过 typed registry 直接复用 Service。除核心 typed 工具外，启动装配会将正式注册的业务 HTTP 路由自动映射为 MCP 工具，参数按 path/query/body/file schema 传递，调用重新经过原 Gin 鉴权、参数校验和 Service；写入、删除及任务控制工具要求 `confirm=true`，文件上传使用 Base64，二进制响应也会编码为 Base64。

### 分享目录脱敏统计（2026-09-08，维护者：Codex）
分享扫描遇到目录名中的连续半角或全角星号时，跳过该目录及其子目录，不发起媒体识别。分享管理媒体统计显示已识别、失败、待识别、脱敏，总数包含脱敏项。历史已保存的脱敏项刷新列表后单独归类；此前扫描时已被丢弃的目录需要重新点击分享的识别按钮补齐统计。同名脱敏目录按目录数量计数，重复扫描不累加。全部媒体已脱敏时识别任务正常完成。

### 批量分享文案解析（2026-09-08，维护者：Codex）

分享管理中的“批量导入分享”先解析预览，再导入勾选记录。支持名称在链接前、后或同一行，Markdown 链接，115.com/s、115cdn.com/s、share.115.com 及缺省协议的分享地址。后端 Service 提取分享编号、名称和访问码，返回统一 https://115.com/s/编号 链接；访问码单独保存，允许在预览修改。保留名称中的容量、部数、年份和版本，去除明确装饰、复制提示和推广文案。

按本次文本的分享编号合并重复；名称和访问码冲突保留候选，名称归属不明或缺失时提示。提示项默认不勾选，用户可修改名称/访问码后勾选。预览显示原文行号及忽略内容。不会核验分享有效性，不与数据库历史记录去重。纯分享链接如未包含名称，需要在预览补充名称。

预览接口 POST /media/share-records/parse 接收 {text}，通过 SuccessResp 返回 records、duplicates、ignored；空文本、无效JSON或没有分享链接返回400。解析不调用网盘、不写库。确认后复用分享创建接口逐条保存；失败停止，已成功项锁定并刷新列表，其余选中项可直接重试。修改原始文本清除旧预览；重新解析只对新文本去重。

### 分享已取消状态（2026-09-08，维护者：Codex）

新增 t_share_record.share_cancelled BOOLEAN NOT NULL DEFAULT FALSE，v24迁移随程序启动在现有事务中执行。识别分享时仅明确的网盘分享取消错误置为true，成功重新解析置为false；任务超时、context取消、密码错误、原因不明的过期/失效不标记。更新状态时核对原链接与密码，避免并发编辑后的旧结果污染。编辑链接/密码自动清除原状态，单纯改名称保留。

列表API返回share_cancelled，名称旁显示红色“分享已取消”标签，刷新后通过数据库字段回显。此次不根据历史任务超时回填取消状态，需重新识别确认。保留原有媒体记录和识别操作。

### 分享剧集海报合并（2026-09-08，维护者：Codex）

列表 Service 对同一分享内已识别成功的电视剧按 TMDB ID（无 TMDB ID 时按元数据源+MetadataID）标记 gallery_duplicate。海报墙默认折叠重复记录，可通过“展开同剧集记录”查看并逐条修正、删除。电影、不同ID、无可信ID或失败记录不按名称合并。该标记由读取时生成，无需迁移或删除历史数据；识别统计仍表示原始记录数量。

扫描判断目录候选仅检查直接子项，避免把集合目录因后代视频误当一部媒体；入库前对已有媒体目录覆盖的 SxxExx 单集候选跳过。裸露在根目录的单集、没有父目录候选的文件和独立电影仍保留，以免丢失混合分享中的内容。

### 清空分享识别内容（2026-09-08，维护者：Codex）

分享管理每行新增“清空识别内容”。确认提示列出分享名称及媒体数量；执行后删除该分享全部 `t_share_media_file` 候选，并清理对应的 `t_share_media` 识别实体，包括已识别、待识别、失败、脱敏和重复单集记录。保留分享主记录、链接、密码及其他配置，不操作115文件。清空完成后可点击“同步分享文件”重新扫描生成候选，再发起识别，不沿用旧单集记录。

DELETE /media/share-records/:id/media 返回 SuccessResp {task_id}，表示接受提交；实际删除数量在任务完成结果中读取。提交时校验目标，目标不存在返回404，非法ID返回400；冲突任务等待当前目标活动单元结束，不取消同步或识别。批量选中分享在同一事务清空，全部清空固定提交时的分享集合。等待期间可取消；进入清理阶段后不可取消。队列适用于当前单后端实例部署。

## 分享资源库与统一定时任务（2026-09-09，维护者：Codex）

分享识别成功时，文件候选才关联新建或已有的 `t_share_media` 实体，并通过实体表的查询投影字段进入作品级资源库；未匹配内容只保留在 `t_share_media_file` 供错误展示和重试。资源库支持 TMDB ID、媒体分类、年份、题材、评分、国家或地区、有效分享和排序筛选，按作品聚合并保留全部分享来源；历史缺失元数据通过任务中心启动可取消的补全任务。

电视剧资源详情按“季 → 集 → 分享文件”展示。季概览来自 TMDB，展开某季时按需读取完整分集目录，并将 `t_share_media_file_episode` 中的本地映射挂到对应集；没有文件的集仍展示，同集多来源和一文件多集均保留。TMDB 暂时不可用或作品没有可用 TMDB 身份时，接口降级返回本地已关联季集并显示警告，不隐藏已有资源。电影继续使用原有来源分页列表。

系统定时任务统一由处理器注册表和 `t_cron_task` 管理，配置包含 Cron 表达式、时区、JSON 参数、启停状态和执行记录。STRM、账号冷却恢复、日志清理和识别缓存清理使用同一调度入口；同一任务或 STRM 配置正在运行时，重复触发会记录为跳过。


### 分享标题与ID识别（2026-09-09，Codex）
保留标题内部数字和中英文混排。已知媒体类型且文件名含[tmdbid=数字]时优先读取TMDB详情；普通查询失败后核对TMDB官方别名，仍要求年份及唯一身份匹配。原始文件路径不修改。


### AI兜底规则（2026-09-09，Codex）
分享识别先执行标题规则、TMDB搜索与官方别名核验，成功则不调用AI。复杂标题及类型不确定场景也在常规识别失败后才触发；仍遵循AI开关与场景配置，一次识别最多调用一次AI，建议必须通过TMDB核验。


### 目录年份回退（2026-09-09，Codex）
剧集查询因目录年份未能确认时，先去掉目录年份重查，再考虑AI；仅接受完整标题对应唯一TMDB身份，同名歧义仍需核对。
