# 产品与架构

- 更新日期：2026-07-23
- 维护者：Codex

## 1. 产品定位

`easy-strm` 是面向个人媒体库的文件整理与 `.strm` 生成工作台。产品聚焦高频、可直接操作的媒体处理流程，不承担资源聚合、下载器管理或完整媒体资产治理平台的职责。

核心流程：

```text
媒体源接入
  -> 文件浏览与选择
  -> TMDB 自动或手动识别
  -> 重命名与整理预览
  -> 移动、复制或链接
  -> 可选元数据刮削
  -> STRM 生成
  -> Emby 刷新与任务追踪
```

## 2. 功能范围

### 2.1 媒体源与文件

- 本地目录与 115 云盘媒体源。
- 媒体源启停、排序、监控目录、整理目标、媒体类型和冲突策略。
- 文件分页浏览、搜索、筛选、面包屑导航与批量选择。
- 本地和 115 文件移动、复制、删除、重命名；本地支持硬链接和软链接。

### 2.2 识别、命名与整理

- TMDB 电影、电视剧搜索和详情查询。
- 文件名解析、自动识别、候选选择、手动修正和缓存回流。
- 电影与电视剧命名模板。
- 整理候选扫描、异步预览、预览恢复、冲突策略和失败项重试。
- 按 Genre、国家/地区、语言、年份和标题关键字配置分类策略。

### 2.3 刮削与 STRM

- 生成电影、剧集 NFO。
- 下载海报、背景图和剧照。
- STRM 配置增删改查、全量生成、任务进度和定时执行。
- 通过公开 `/direct-link` 接口解析 115 播放直链。
- 整理完成后可生成 STRM 并触发 Emby 刷新。

### 2.4 自动化与运维

- 本地目录实时监控、115 目录轮询与自动整理。
- 自动整理失败分类、取消和重试。
- 统一任务列表、详情、进度、结果与失败信息。
- Dashboard、日志、网络检测、Redis 缓存管理和系统配置。
- Telegram、Server 酱和 SMTP 通知后端。
- Docker Compose 部署 PostgreSQL、Redis 和应用服务。

## 3. 已下线范围

2026-07-23 起，下列低频功能不再属于产品范围：

- 媒体资产台账。
- 媒体源全量/增量同步及同步索引。
- 入库流水线。
- 识别失败待处理清单。
- 任务持久化步骤时间线。
- 115 生活事件增量同步。
- 系统设置中的全局 Alist 地址和令牌配置。

代码不再注册相关页面或接口，也不再为新环境创建对应数据库表。历史数据库中的旧表和旧配置行不会由应用启动过程自动删除。

## 4. 页面结构

### 支撑配置

- 文件工作台
- STRM 配置
- 115 云管理
- 整理规则
- 系统设置

### 运维观察

- 系统日志
- 网络测试
- 缓存管理

## 5. 技术架构

| 层级 | 技术与职责 |
| --- | --- |
| 前端 | Vue 3、Vite、Naive UI、Tailwind CSS；页面与交互编排 |
| Controller | Gin HTTP 参数、响应和路由适配 |
| Service | 识别、整理、刮削、STRM、监控和任务业务流程 |
| DAO | PostgreSQL、Redis 持久化访问 |
| 外部适配 | 115、TMDB、Emby、通知和本地文件系统 |

依赖方向：

```text
Vue 页面 -> utils/api -> Controller -> Service -> DAO/外部适配
```

## 6. 当前边界与限制

- STRM 增量生成接口尚未实现，应使用全量生成。
- 115 开放平台登录等待开发者账号，当前主要使用 Cookie 扫码登录。
- 真实 TMDB、115、Emby 和通知成功链路依赖用户环境配置。
- 当前为单工作台登录模式，不提供多用户角色权限。
- 不接入 PT、下载器、资源搜索、订阅和插件市场。

## 7. 演进原则

后续优先稳定文件工作台主链路，减少并行产品面。新增能力必须直接服务于“浏览、识别、整理、刮削、STRM、追踪”之一，并复用现有 Service、API 和 UI 体系。
