## 四、发现的Bug清单

### Bug #1: 115客户端未初始化导致文件浏览失败

**Bug ID**: MEDIA-001
**严重级别**: P0 (阻断性)
**影响模块**: 媒体管理 - 文件浏览
**发现时间**: 2026-04-01 23:22:37

#### 复现步骤
1. 登录系统获取Token
2. 调用 `GET /media/files?source_id=15&path=&page=1&page_size=20`
3. 观察返回结果

#### 预期结果
返回115网盘根目录的文件列表,包含文件名、大小、类型等信息。

#### 实际结果
```json
{
  "error": "115客户端未初始化"
}
```

#### 错误日志
```
[文件浏览] 浏览根目录-1: 获取失败: None
Details: {
  "response": {
    "error": "115客户端未初始化"
  }
}
```

#### 根因分析
1. **代码层面**: 检查 [media_source_controller.go:306-309](file:///c:/Users/a3875/Documents/code/easy-strm/easy-strm/internal/controller/media_source_controller.go#L306-L309)
   ```go
   client, ok := ctx.Get("115client")
   if !ok {
       return nil, fmt.Errorf("115客户端未初始化")
   }
   ```

2. **问题定位**: 115客户端未在请求上下文中正确注入

3. **可能原因**:
   - 中间件未正确初始化115客户端
   - 115账号Cookie失效或无效
   - 115客户端初始化逻辑缺失

#### 影响范围
- 所有115数据源的文件浏览功能不可用
- 所有115数据源的文件搜索功能不可用
- 影响2个已配置的115数据源 (ID: 14, 15)

#### 建议修复方案
1. **短期方案**: 在文件浏览接口中动态初始化115客户端
   ```go
   // 在 getCloud115Files 方法开始处添加
   cloud115, err := c.cloud115Service.GetByID(*source.Cloud115ID)
   if err != nil || cloud115 == nil {
       return nil, fmt.Errorf("115账号不存在")
   }

   // 初始化115客户端
   client, err := driver.New(driver.WithCookie(cloud115.Cookie))
   if err != nil {
       return nil, fmt.Errorf("115客户端初始化失败: %v", err)
   }
   ```

2. **长期方案**: 实现中间件统一注入115客户端
   - 在JWT中间件之后添加115客户端中间件
   - 根据请求参数中的source_id自动注入对应的115客户端
   - 添加客户端连接池管理,避免重复初始化

## 五、接口设计问题分析

### 5.1 API路径不一致问题

**问题描述**:
- 实际路由: `/media/sources`
- 前端调用: `/api/media/sources` (根据前端代码)
- 文档定义: `/api/media/sources` (根据PRD文档)

**影响**:
- 前端需要配置代理转发
- API文档与实际不符

**建议**:
统一API路径规范,建议使用 `/api` 前缀,便于:
1. 区分API路由和静态资源路由
2. 便于Nginx反向代理配置
3. 符合RESTful API最佳实践

### 5.2 登录接口字段命名不一致

**问题描述**:
- 登录接口使用 `name` 字段
- 前端可能使用 `username` 字段

**建议**:
统一字段命名,建议使用 `username`,更符合用户习惯。

### 5.3 密码传输方式

**问题描述**:
- 前端需要发送MD5哈希值
- 缺少前端密码加密说明文档

**建议**:
1. 在API文档中明确说明密码需要MD5加密
2. 或改为后端接收明文密码并加密,提升安全性
