| E2E 测试（D7-D8） | D7-D8 | E2E 覆盖率降低，核心手动回归测试替代 | 迭代 2 首个工作日补充 |
| 性能压测报告（D7 BE-1） | D7 | 缺少性能基线，但不阻塞发布 | 迭代 2 嵌入 |

**最小可交付集（延期 2 天的极限）**：
- `POST /api/115/share/parse` + `POST /api/115/share/transfer` + `GET /api/115/share/transfer/{id}/progress`
- 前端：链接输入 → 解析 → 文件树展示 → 勾选 → 转存 → 进度轮询
- 去 WebSocket、去 PostHog 前端埋点、去 E2E、去性能报告

##### 情景 B：115 API POC 失败（分享解析接口不可用）

| 备选方案 | 说明 | 切换成本 | 用户体验降级 |
| --- | --- | --- | --- |
| **方案 B1：手动 CID/pickcode 输入** | 用户在 115 客户端获取文件的 cid/pickcode，粘贴到 easy-strm 进行转存 | 后端改动 ≤1d（去掉 URL 解析，保留目录树+转存逻辑） | 用户需要多一步手动操作，但转存+整理闭环仍完整 |
| **方案 B2：115 分享链接页面 DOM 解析（如有 Web 版分享页）** | 模拟浏览器访问 115 分享页面，从 DOM 提取文件列表 | 调研 2-3d + 实现 2d | 存在反爬风险、页面结构变化等稳定性问题 |
| **方案 B3：降级为手动文件管理增强** | 推迟分享解析，优先增强文件工作台的批量操作能力 | 重新规划工作量 | MVP 不再包含分享解析，变为文件工作台增强版 |

**推荐**：方案 B1 作为 POC 失败后的首选降级，保留转存→整理核心链路。
