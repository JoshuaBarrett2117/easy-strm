## 3. 竞品动态

> 综合竞析报告结论及用户研究报告 11.1 竞品格局分析。

### 3.1 竞争格局一览

| 竞品 | 类型 | 核心缺陷（与资源聚合相关） | easy-strm 差异化 |
| --- | --- | --- | --- |
| **Sonarr/Radarr** | 自动化工具 | 无中文优化；无 115 支持；配置复杂 | 中文 UX + 115 原生 + 一站式 |
| **NasTool** | 综合管理 | 维护状态不确定；稳定性存疑 | 独立开源、社区驱动、轻量 |
| **tinyMediaManager** | 桌面应用 | 仅本地；无资源获取；无 Web | Web 化 + 资源聚合 + 自动化管道 |
| **MovieRobot** | 组合方案 | 配置碎片化；各工具衔接差 | 统一入口、单一配置 |
| **手动脚本（GitHub 各类）** | 脚本 | 无 UI；维护成本高 | GUI + 任务管理 + 容错 |
| **NAS 套件** | 集成 | 封闭；刮削弱；无 115 | 跨平台 + STRM + 灵活性 |

### 3.2 easy-strm 的差异化机会

**核心空白（8 竞品全部空白）**：**115 分享链接解析 → 自动转存 → 自动整理 → STRM → Emby 播放** 这条完整闭环链路。

- 115 网盘在中文媒体服务器圈子有独特地位（大容量+低成本+直链），且 easy-strm 已深度整合 115 API。
- 市面上没有任何工具实现"115 分享 → STRM"的自动化。

### 3.3 技术路径建议（竞析结论）

| 阶段 | 内容 | 预估迭代 | 切入点 |
| --- | --- | --- | --- |
| Phase 1 | 115 分享链接解析→自动转存 | 1-2 | 最高 ROI，已有 115 API 基础 |
| Phase 2 | Mikan RSS 番剧订阅 | 2-3 | 番剧用户刚需，中文动漫 RSS 索引站 |
| Phase 3 | Prowlarr API 集成 | 3-5 | 复用现有索引器生态，不自建索引 |
| Phase 4 | Telegram Bot 集成 | 远期 | 低频需求、合规风险需评估 |

### 3.4 核心原则

1. **索引器复用优于自建**：通过 Prowlarr/Jackett 复用现有索引器生态，不投入资源自建搜索/爬虫。
2. **115 优先于通用 BT**：先打透 115 场景（差异化空白），再扩展到通用 BT/PT 场景。
3. **窗口期判断**：NasTool 维护不确定性给 easy-strm 留出 3-6 个月窗口，应在此期间完成 115 转存 + 追剧订阅的 MVP，建立用户心智。

### 4.2 Q3 2026 — 资源聚合 MVP：115 分享转存

**主题说明**：

这是资源聚合功能的起点，也是 ROI 最高的切入口。选择"115 分享链接转存"作为 MVP 的理由：

1. **战略对齐度最高**（数析报告 ROI 评分 0.64，P0 强烈推荐）：easy-strm 已有的 115 API 深度整合是核心竞争力，扩展为"分享→转存→整理→STRM"闭环几乎没有竞品。
2. **用户需求最紧迫**（用户报告 P0 排序第一）：115 分享链接是中文媒体服务器用户最常用的资源获取方式，但当前流程断裂——用户在 115 App 里手动转存，再回到 easy-strm 触发整理。
3. **实现复杂度最低**（数析报告 IC=2/5）：基于已有 115 API 基础，核心工作为 URL 解析、目录树展示、文件选择、转存触发，可在 2 个迭代（4 周）内完成。
4. **为后续功能打基础**：转存流程中沉淀的"资源源→文件→选择→动作"抽象层，可直接复用于 Q4 的追剧订阅和 Q1 的 PT 站 RSS。

**关键交付物**：

| 交付物 | 说明 |
| --- | --- |
| **115 分享链接解析器** | 支持标准 115 分享链接（含加密链接），解析出目录结构和文件列表，展示文件名、大小、类型 |
| **文件选择与转存界面** | 树形/列表混合展示分享内容；支持全选/反选/按类型筛选；展示转存目标路径、空间余量检查 |
| **转存→整理自动触发** | 转存完成后自动触发已有 Watch/Cron 流程（复用现有基础设施）；提供"转存后立即整理"一键开关 |
| **转存任务管理** | 在任务中心新增"资源聚合"类型，展示转存进度、成功/失败文件列表、冲突处理结果 |
| **行为埋点基础设施** | 部署 PostHog 开源版（Docker），前端页面事件 + 后端 Service 层关键动作埋点，建立第一条行为基线 |

**依赖项**：

| 依赖 | 状态 | 负责人/来源 |
| --- | --- | --- |
| 115 API 现有封装（login/file/list/copy） | ✅ 已有 | easy-strm 后端 |
| Watch/Cron 自动整理基础设施 | ✅ 已有 | easy-strm 后端 |
| 任务中心框架 | ✅ 已有 | easy-strm 前后端 |
| PostHog 部署与数据管道 | 🔲 待启动 | DevOps |
| 115 分享链接格式文档（内部） | 🔲 需调研 | 后端开发 |

**风险与缓解**：

| 风险 | 严重度 | 缓解措施 |
| --- | --- | --- |
| **115 API 策略变动**：分享链接解析接口可能被 115 限制或调整 | 🟡 中 | 后端 115 Client 层抽象统一，策略变动仅影响一个模块；提供手动输入 CID/pickcode 的 fallback 路径 |
| **转存大目录超时**：分享链接包含数千文件时，解析和转存可能超时 | 🟡 中 | 分页解析（每页 100 条）；转存任务异步化，后端队列处理 |
| **用户认知门槛**：用户不熟悉"资源聚合"概念 | 🟢 低 | 在文件工作台增加"从 115 分享添加"入口按钮，配合简单引导文案 |

### 4.3 Q4 2026 — 追剧订阅 + Mikan RSS 番剧

**主题说明**：

**关键交付物**：

### 4.4 Q1 2027 — PT 站 RSS + Prowlarr 集成

**主题说明**：

Q1 2027 将资源聚合从 115 和 Mikan 场景扩展至更通用的 BT/PT 生态。通过集成 Prowlarr/Jackett，easy-strm 可复用数十个现有索引器，无需自建搜索爬虫（遵循"索引器复用优于自建"原则）。PT 站 RSS 订阅是影音发烧友的核心刚需，同时解决 PT 用户的 ratio 维持需求。

**关键交付物**：

| 交付物 | 说明 |
| --- | --- | --- |
| **PT 站 RSS 订阅监控** | 支持配置多个 PT 站 RSS 源；定时轮询+过滤规则（free/2x/HR 等促销标记）；自动推送到下载器 |
| **Prowlarr/Jackett API 集成** | 通过 Prowlarr API 获取已配置的全部索引器；统一搜索接口（按标题/TMDB ID 搜索）；结果聚合呈现（去重+排序） |
| **种子健康管理** | 展示种子上传量/下载量/分享率/做种时间；自动暂停比率过低或健康度过低的种子；PT 站全局 ratio 面板 |

  1. **Q3 MVP 上线后 4 周**：115 分享转存使用率是否达到预期的 30%？（首次订阅/转存完成率目标）如不达标，暂停 Q4 追剧/番剧，转为优化核心整理体验。

- **版权合规是红线**：每个阶段都要求前置合规评估。产品定位始终是"工具提供方"（不预置内容源、不存储/分发内容）。使用协议会持续更新以覆盖新的功能模块。
- **资源投入可控**：峰值人力为 2-3 后端 + 1-2 前端，团队规模要求不高；第三方依赖多为开源、API 公开、自部署，无大额第三方服务费。

### C. 术语表

| 术语 | 含义 |
| --- | --- |
| STRM | Stream Redirect Media，流媒体重定向文件，用于在 Emby/Jellyfin 中播放 115 云盘等远程存储的媒体内容 |
| Watch | easy-strm 的文件系统监控功能，监控指定目录的文件变更新，自动触发整理流程 |
| Cron | easy-strm 的定时任务功能，按 Cron 表达式周期触发 STRM 生成 |
| Pipeline | 资源聚合的全链路自动化流程：资源发现 → 获取 → 整理 → STRM → Emby |
| 资源源（ResourceSource） | 资源聚合功能中抽象的资源来源概念，包括 115 分享链接、追剧订阅、RSS 源、PT 站、Prowlarr 索引器等 |
| 转存 | 将 115 分享链接中的文件复制到用户自己的 115 网盘中 |
| Prowlarr/Jackett | 开源索引器管理工具，聚合管理多个 BT/Usenet 索引器，提供统一搜索 API |
| Mikan | 中文动漫 RSS 索引站 |
| PostHog | 开源产品分析平台，用于用户行为埋点和数据分析 |
| WAO | Weekly Active Organizers，每周成功完成"资源获取→整理→STRM"全链路的用户数，本次定义的北极星指标 |
